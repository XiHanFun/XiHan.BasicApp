配置参考 ​

本页说明宿主与前端的全部配置项、缺省值与含义，适用于开发、部署与运维时查阅。键与缺省值以 backend/src/XiHan.BasicApp.Host/appsettings.json 为准。

文件与优先级 ​

宿主是标准 ASP.NET Core 应用，配置按顺序叠加，后者覆盖前者：appsettings.json → appsettings.{环境}.json → 用户机密（只在 Development）→ 环境变量 → 命令行参数。环境由 ASPNETCORE_ENVIRONMENT 决定：本机开发是 Development（launchSettings.json 已设），部署时缺省是 Production。

环境变量用双下划线分节，如 XiHan__Security__Jwt__Secret；数组写下标，如 BasicApp__Cors__AllowedOrigins__0。

配置分两组：

  • 框架节 XiHan:*：由 XiHan.Framework 的各个 Feature 读取。写了就校验，类型、范围或枚举值不合法时启动即失败。列表与字典（如 Exclude、Routes、AllowedHosts）没有内容时整项不写：空的 [] / {} 会被读成空字符串而启动失败，JSON Schema 会把它们标为错误。
  • 应用节 BasicApp:*：由各能力包的 Options 直接绑定。除特别注明的几节外，写错同样启动即失败，不会退回缺省值。

appsettings.json 写出了全部配置项：写出来的值就是缺省值（个别是 BasicApp 的推荐值，下文写明），注释掉的是可选项，去掉 //、填上真实值即生效。文件里不逐项注释，每一项的说明在下文与 JSON Schema（编辑器里悬停可见）。

文件入库用途
appsettings.json是全部配置项与缺省值，所有环境共用
appsettings.Development.json是本机开发：开发库连接、开发用密钥，启动时建库、建表并执行种子
appsettings.Production.json否（.gitignore）正式环境的真实值：数据库、密钥、对外地址等；也可以全部改用环境变量
ConfigurationSchema.json是XiHan 与 BasicApp 两节的 JSON Schema，见 JSON Schema

不提交密钥

appsettings.json 里的 JWT 密钥、签名地址密钥都留空，也不写数据库连接；appsettings.Development.json 里的值只用于本机开发。部署时写进不入库的 appsettings.Production.json，或由环境变量、密钥存储提供，下文示例一律用占位符。

JSON Schema ​

backend/src/XiHan.BasicApp.Host/ConfigurationSchema.json 描述 XiHan 与 BasicApp 两节的每个键：类型、枚举值、取值范围、缺省值与说明（框架的键取自 XiHan.Framework 的配置索引）；框架节的列表与字典要求非空，写成空的 [] / {} 即报错。Kestrel、Logging 等 ASP.NET Core 自带的键由编辑器内置的 appsettings Schema 描述。

  • Visual Studio：宿主工程把它登记为 JsonSchemaSegment，打开任一 appsettings*.json 即有补全、悬停说明与类型校验，不用另外配置。
  • VS Code：在 .vscode/settings.json 里映射（可以和 ASP.NET Core 的 Schema 一起用）：
json
{
  "json.schemas": [
    {
      "fileMatch": ["backend/src/XiHan.BasicApp.Host/appsettings*.json"],
      "url": "./backend/src/XiHan.BasicApp.Host/ConfigurationSchema.json"
    },
    {
      "fileMatch": ["backend/src/XiHan.BasicApp.Host/appsettings*.json"],
      "url": "https://json.schemastore.org/appsettings.json"
    }
  ]
}
  • Rider：在「JSON Schema Mappings」里把同样的文件指向 ConfigurationSchema.json。

加配置项时同步补 Schema：架构测试 ConfigurationSchemaTests 核对 appsettings.json 与 appsettings.Development.json 里 XiHan、BasicApp 下写出的每个键都在 Schema 里，漏了即失败。

ASP.NET Core ​

Kestrel ​

键缺省说明
Kestrel:Endpoints:Http:Urlhttp://localhost:9710操作接口、OpenAPI、MCP、SignalR Hub 与文件端点。容器或对外部署改成 http://0.0.0.0:9710，HTTPS 由反向代理终止
Kestrel:Endpoints:Grpc:Urlhttp://127.0.0.1:9711gRPC（Protocols: Http2），只供内部服务调用，只监听内网地址

Logging 与 AllowedHosts ​

键缺省说明
Logging:LogLevel:DefaultInformation键是日志类别前缀（取最长匹配）
Logging:LogLevel:Microsoft.AspNetCoreWarningASP.NET Core 的请求日志只记警告以上
Logging:LogLevel:XiHan不写（Development 为 Debug）框架日志
AllowedHosts*允许的 Host 请求头，分号分隔

日志同时经 OpenTelemetry 导出，见 XiHan:Observability。

XiHan:Kernel ​

键缺省说明
StartTimeoutSeconds60单个特性的启动超时；框架缺省 30，BasicApp 取 60，因为表结构升级与开发环境建表都在启动阶段
StopTimeoutSeconds30单个特性的停止超时
FailurePolicyTerminateStartup特性启动失败时终止启动；IsolateFeature 隔离该特性继续启动
UseBuiltInMiddlewaretrue内核内置的观测、截止时间、韧性与输入校验中间件；不要关

XiHan:Kernel:Resilience ​

按操作 ID 的固定窗口限流、并发上限与熔断。根上的键是全部操作的缺省策略，Operations:<操作 ID> 按操作覆盖（子键相同，不写的沿用缺省策略）。缺省不限流、不限并发、不熔断。

键缺省说明
PermitLimit不写（不限流）固定窗口内允许的调用数
WindowSeconds1限流窗口
QueueLimit0窗口用尽时排队的调用数，0 为直接拒绝
ConcurrencyLimit不写（不限）同时执行的调用数上限
ConcurrencyQueueLimit0并发用尽时排队的调用数
FailureThreshold不写（不熔断）连续失败多少次后熔断
BreakSeconds30熔断后拒绝调用的时长，到期放一次试探
json
{
  "XiHan": {
    "Kernel": {
      "Resilience": {
        "Operations": { "auth.login": { "PermitLimit": 20, "WindowSeconds": 1 } }
      }
    }
  }
}

操作 ID 用 dotnet run --project backend/src/XiHan.BasicApp.Host -- operations 列出。

XiHan:Bindings:db ​

平台库连接，启动硬要求：缺失即 RUNTIME_VALIDATION_001 中断启动，不退回内存实现；provider 不写即 postgresql。

框架先读 SERVICE_BINDING_ROOT 目录（Kubernetes Service Binding），再读配置节；配置节里的同名绑定会整个盖掉目录里挂进来的（值为空也一样），所以 appsettings.json 不写任何绑定。本机开发写在 appsettings.Development.json，部署用环境变量 XiHan__Bindings__db__value 或 Service Binding（db 目录下放 type、uri，可选 provider）。绑定名与属性名一律小写。

json
{
  "XiHan": {
    "Bindings": {
      "db": {
        "type": "connection:relational",
        "value": "Host=<主机>;Port=5432;Database=<库名>;Username=<用户>;Password=<密码>",
        "provider": "postgresql"
      }
    }
  }
}

独立库租户的连接串不写在配置里：由 tenants.configure-database 写进租户目录，以 ISecretProtector 密文存放。

分布式缓存与消息 ​

不配即单机：缓存与消息走框架的进程内实现，零外部依赖。配了连接，宿主就装上对应的 Provider，多个实例共享缓存与消息；配了而连不上，启动即失败，不退回内存实现。

连接（任选一处）装上的 Provider健康项
绑定 XiHan:Bindings:cache（类型 cache:distributed）或 XiHan:Caching:Redis:ConfigurationCaching.Redis：ISharedCache、字节存储、分布式锁与幂等去重；Caching.Hybrid：ICache 成为本机 L1 + Redis L2，写入经 Redis 频道失效各实例的 L1caching.redis.connection
绑定 XiHan:Bindings:queue（类型 queue）或 XiHan:Messaging:RabbitMQ:ConfigurationMessaging.RabbitMQ：发件箱派发、CloudEvents 发布模式与广播订阅经它，各实例按主题竞争消费messaging.rabbitmq.connection
json
{
  "XiHan": {
    "Bindings": {
      "cache": { "type": "cache:distributed", "value": "<主机>:6379", "password": "<密码>" },
      "queue": { "type": "queue", "value": "amqp://<主机>:5672", "username": "<用户>", "password": "<密码>" }
    }
  }
}

部署时用环境变量 XiHan__Bindings__cache__value、XiHan__Bindings__queue__value 或 Service Binding（SERVICE_BINDING_ROOT 下的 cache / queue 目录）提供。绑定与 Configuration 键都配了时绑定优先，绑定的值为空才读 Configuration。口令可以写进连接串，也可以放在绑定的 username / password 属性里（Service Binding 目录里的同名文件），各自覆盖连接串里的用户名与密码。

XiHan:Caching ​

键缺省说明
InMemory:MaxEntries10000进程内缓存每张表（字节存储、对象缓存各一张）的条目上限；没配 Redis 时生效
InMemory:DefaultTimeToLiveSeconds300进程内缓存未指定过期时的存活时间
Idempotency:TimeToLiveSeconds86400幂等去重：已完成结果的保留时间
Idempotency:InProgressTimeToLiveSeconds60处理中标记的保留时间，即处理器崩溃时的最长封锁
Redis:Configuration不写StackExchange.Redis 连接串；绑定 cache 优先
Redis:KeyPrefixxihan:键前缀；同一个 Redis 给几套环境用时各取一个
Redis:PublishChangestrue写入与删除后向频道 <前缀>__changes 发通知，各实例据此失效 L1
Redis:DefaultTimeToLiveSeconds300未指定过期时的存活时间
Redis:HealthProbeIntervalSeconds15健康项的重探间隔与单次探测超时
Hybrid:LocalCapacity / Hybrid:LocalTimeToLiveSeconds10000 / 30本机 L1 的条目上限与存活上限；收不到变更通知时，别的实例的写入最迟这么久后可见

Redis:* 与 Hybrid:* 只在配了 Redis 时生效。

XiHan:Messaging ​

键缺省说明
MaxAttempts3消息代理把一条消息投递给处理器的最多次数（含首次），超过进入死信
DeadLetterSuffix.dlq死信主题后缀
InstanceId每次启动随机本实例在消息代理上的标识：1–64 个字母、数字或 ._-，字母或数字开头。配了就必须每个实例各不相同（多副本可设成 Pod 名）；不配即可
InMemory:MaxQueuedMessages10000进程内消息每个主题（含死信）的条目上限；没配 RabbitMQ 时生效
Outbox:PollIntervalSeconds1发件箱轮询间隔
Outbox:BatchSize100每轮最多投递的条数（1–1000），也是每轮最多清理的已投递行数
Outbox:MaxAttempts10发件箱投递到消息代理的最多次数（含首次），用尽进死信；与上面的 MaxAttempts 是两层
Outbox:RetryDelaySeconds / Outbox:MaxRetryDelaySeconds5 / 300首次失败后的重试间隔（之后每次翻倍）与上限
Outbox:DispatchedRetentionSeconds86400投递成功的行保留多久，0 为成功即删除；死信行不自动删
Outbox:IncludeShardsfalse（框架缺省 true）是否也逐个轮询租户独立库里的发件箱；SqlSugar 把发件箱行留在平台库，BasicApp 关掉以省去每个独立库一轮的多余查询
Outbox:ShardRefreshIntervalSeconds60独立库清单多久从租户目录重读一次，IncludeShards 打开时才用到
RabbitMQ:Configuration不写AMQP URI（amqp:// 或 amqps://）；绑定 queue 优先
RabbitMQ:Exchangexihan发布用的持久 direct 交换机；不能为空、不能以 amq. 开头，已有同名但不是持久 direct 的交换机即启动失败
RabbitMQ:QueuePrefixxihan.订阅方声明持久队列 <前缀><主题>；没人订阅的主题发布即丢弃，不堆积
RabbitMQ:PrefetchCount16每个消费者的预取数（1–65535）
RabbitMQ:HealthProbeIntervalSeconds15健康项的重探间隔与单次探测超时

目前的消息处理器：Realtime 的断开连接（广播订阅，RabbitMQ 上按 InstanceId 给每个实例建自己的队列）、Chat 订阅 Organization 的部门归属变更（领域事件，见实体基类），以及 Workflow 订阅引擎的任务创建、转办与实例故障（发待办与故障通知）。邮件、短信与机器人消息的发送记录是应用表，不经消息代理。

XiHan:Persistence:SqlSugar ​

键缺省说明
InitTablesfalse（Development 为 true）启动时按实体建缺表、加缺列；只用于开发，正式环境由 Schema/ 脚本管理
CommandTimeoutSeconds300语句超时，正整数
HealthProbeIntervalSeconds15健康项 persistence.sqlsugar.database 的重探间隔与单次探测超时
Connections:<名>不写命名连接，值是连接串；名字合 ^[a-z0-9][a-z0-9-]{0,63}$，不能是 default 或 shard。目前只有 SQLite 上的工作流租约表需要
Replicas:DefaultHitRate10没写权重的从库的读权重
Replicas:HealthChecktrue周期探测从库：连不上的自动摘除、恢复后加回；关掉后宕机的从库照常接读流量
Replicas:HealthCheckIntervalSeconds30探测间隔
Replicas:FailureCooldownSeconds120从库最后一次失败后，过了这么久并且探通才恢复读流量

从库本身在 BasicApp:Database 配，健康快照看 persistence.sqlsugar.replicas。

XiHan:Persistence:DataSources ​

运行时数据源，即代码生成登记的外部数据库。

键缺省说明
MaxCount64登记数上限（1–1024）；满了再登记新名字即失败，不淘汰已有的
HealthProbeIntervalSeconds15健康项 persistence.datasource.<名> 的重探间隔，也是连接测试的单次上限

XiHan:ObjectStorage ​

BasicApp 的存储（本地目录、S3 兼容）在后台「存储配置」页面维护，本地根目录见 BasicApp:Files。框架的 XiHan:ObjectStorage:S3 节不读取，不用写。

键缺省说明
StoreHealthProbeIntervalSeconds15各存储实例健康项 objectstorage.store.<名> 的探测间隔
SignedUrls:Secret空本地存储签名下载地址（宿主 /blobs 端点）的 HMAC-SHA256 密钥，UTF-8 至少 32 字节，多实例必须一致；缺失或太短启动即失败。S3 兼容存储由存储自己签名，不用它
SignedUrls:BaseUrl/blobs地址前缀：以 / 开头的路径，或不带查询串的绝对 http(s) 地址
FileSystem:RootPath程序目录下的 blobs框架缺省的文件系统存储；业务不用它，只是启动时会建出这个目录
FileSystem:MaxTotalBytes / MaxBlobBytes / MultipartExpiryHours / MaxMultipartUploads1 GiB / 256 MiB / 168 / 1000同上，总字节（暂存的分片也计入）、单个对象字节、未完成分片的保留时长（过期即拒绝）与未完成分片上传数的上限
Stores:<名>不写命名存储实例（filesystem 或 s3）；业务不按名取用，不要用 local 与 storage-* 这两类名字

XiHan:Security ​

键缺省说明
RequireAuthenticationfalse为 true 时匿名调用一律拒绝；BasicApp 由各操作的权限与策略决定，保持 false
RoleClaimrole令牌里承载角色的声明
Jwt:Secret空HS256 对称密钥，UTF-8 至少 32 字节，缺失或太短启动即失败；Identity 签发与框架校验共用，Hub 的认证也用它；多实例必须一致
Jwt:Issuer / Jwt:Audiencexihan.basicapp写了就按它校验，整项不写才不校验；写成空串不等于不写
Jwt:ClockSkewSeconds60校验有效期时允许的时钟偏移
Jwt:NameClaimsub作为主体 ID 的声明
Database:CacheSize10000授予缓存条目上限（每个主体与租户组合一条），满时整体清空

Ip2Region:V4Database / V6DatabaseIpDatabases/ip2region_v4.xdb / IpDatabases/ip2region_v6.xdbIP 归属地离线库（随发布目录分发），相对路径按程序目录；文件缺失不影响启动，首次查询记一条警告，之后该类地址没有归属地；写成空白启动即失败

XiHan:Security:Outbound ​

出站地址策略：向用户填的地址发请求时能连哪些 IP。缺省只能连公网地址，回环、私网、链路本地和云元数据地址都拒绝。检查放在建立连接时，按解析出的实际 IP 判，重定向也一样，DNS 重绑定绕不过去。

受这道策略约束的：工作流 Http 活动、群机器人 Webhook、SMTP 服务器、AI 提供商地址、第三方登录、S3 兼容存储、代码生成的外部数据源、CloudEvents 出站 Webhook、Telegram（配了代理时不受约束，代理地址只有平台管理员能配）。

键缺省说明
AllowLoopbackfalse（Development 为 true）放行回环地址（127.0.0.0/8、::1）；生产环境不要打开
AllowPrivateNetworkfalse放行私网地址（10/8、172.16/12、192.168/16、fc00::/7），不含链路本地与云元数据地址
AllowedNetworks不写放行的网段（CIDR，主机位为 0），优先于全部拒绝规则

TwoFactorTicketMaxFailures5一张票据允许输错的次数，用完即作废、须重新登录
TotpIssuerXiHan BasicApp认证器 App 里显示的签发方
SelfRegistrationEnabledfalse开放自助注册（auth.register，注册的是平台账号）
VerificationCodeMinutes10邮件 / 短信验证码有效期
VerificationCodeIntervalSeconds60同一用途、同一目标两次发码的最短间隔
VerificationCodeDailyPerTarget / VerificationCodeDailyPerAddress10 / 50一个邮箱或手机号、一个客户端地址每天（UTC）最多收发几次，不分用途
VerificationCodeMaxFailures / VerificationCodeLockoutMinutes5 / 10一个验证码允许输错的次数；用完后同一用途、同一主体不能再发码与校验的时长

登录页开放哪些方式不在这里，而是系统参数 identity.login-methods（JSON 数组：password、email、phone、passkey），见系统设置。

BasicApp:Auth:OAuth（第三方登录） ​

第三方登录不分租户、不存库；启用且填了 ClientId 的提供方才出现在登录页。第三方账号要先在个人中心绑定本地账号才能登录，不自动建号。

键缺省说明
Enabledtrue总开关；没有可用的提供方时等于关
FrontendCallbackUrl/#/auth/oauth-callback回调后带着一次性票据跳去的前端页面
CallbackBaseUrl不写（取请求的来源）回调地址的来源（协议 + 主机 + 端口）；经反向代理时要么写它，要么保证转发头配置正确
Providers[]提供方列表，按顺序显示，同名只取第一个

在第三方后台登记的回调地址是 <CallbackBaseUrl>/api/oauth/<Name>/callback。

json
{
  "BasicApp": {
    "Auth": {
      "OAuth": {
        "CallbackBaseUrl": "https://<后端对外地址>",
        "Providers": [
          { "Name": "github", "ClientId": "<客户端 ID>", "ClientSecret": "<客户端密钥>" },
          { "Name": "wecom", "ClientId": "<corpid>", "ClientSecret": "<应用 secret>", "AgentId": "<AgentId>", "Mode": "QrCode", "LoadMemberProfile": true }
        ]
      }
    }
  }
}

提供方的字段：

字段说明
Name路由与登录页用的名称（小写）
Provider类型，不写即按 Name 判定：github、gitee、google、qq、wechat（别名 weixin）、wecom（别名 workweixin）、lark（别名 feishu）、dingtalk
ClientId / ClientSecret应用凭据（微信为 appid / secret，企业微信为 corpid / 应用的 corpsecret）
Enabled / DisplayName缺省 true；登录页上的显示名，缺省同 Name
ModeQrCode（扫码，缺省）或 Account（账号授权：微信公众号网页授权、企业微信网页授权、飞书、钉钉账号登录）
AgentId / CorpId / LoadMemberProfile企业微信的应用 AgentId；钉钉限定组织；企业微信再取成员资料（姓名通常只在这里有）
Scopes / AuthorizationEndpoint额外的授权范围（微信、企业微信整体替换缺省，其余追加）；授权页地址覆盖

BasicApp:Access ​

键缺省说明
PermissionConditionModeEnforce权限条件的生效模式：Enforce（判定）、LogOnly（只记日志不拦截）、Disabled（不判定）
AccessPolicyEnabledtrue访问策略总开关；策略把自己锁在外面时由运维在这里关掉
ConditionTimeZoneAsia/Shanghai条件里时刻、小时、星期与日期所按的时区（IANA 或 Windows 写法）

BasicApp:Auditing ​

BasicApp 自己的访问、异常、登录与变更日志，按月分表。

键缺省说明
QueueCapacity10000等待落库的日志条数上限；满了新到的丢弃并计数，不阻塞调用
BatchSize / FlushIntervalSeconds200 / 1每批落库的条数与刷写间隔（秒，可带小数）
AccessLog:Enabledtrue是否记访问日志
AccessLog:Exclude[]不记访问日志的操作 ID，如 auth.me；异常、登录与变更日志不受影响
DefaultRetentionDays180系统参数 auditing.retention-days 的值为空时的保留天数
RetentionCron0 3 * * *保留清理作业的计划（cron，按 UTC）

BasicApp:Files ​

上传、分片与签名下载地址；存储本身在后台「存储配置」里维护。这一节写错不报错：不合法或不是正数的值按缺省值处理。

键缺省说明
LocalRootPathApp_Data/files本地存储根目录，相对路径按内容根目录；各本地存储配置的桶是它下面的子目录
MaxUploadBytes104857600（100 MiB）单个文件的大小上限
UploadPartBytes8388608（8 MiB）分片上传每片的大小，不小于存储要求的最小分片 5 MiB
UploadLifetime1.00:00:00分片上传从发起到完成的时限
LinkLifetime / MaxLinkLifetime00:30:00 / 7.00:00:00签名下载地址的缺省与最长有效期

BasicApp:Notification ​

邮件、短信、机器人发件箱与 Telegram 交互；通道与机器人在后台页面配置。这一节写错不报错：不合法的值按缺省值处理。

键缺省说明
Brand不写（应用名）邮件与短信模板变量 brand 的缺省值
DispatchInterval00:00:05发送循环的轮询间隔；有新记录时提前唤醒
RetryDelay00:00:30失败后重试的基础间隔，第 n 次失败后等 n 倍
MaxAttempts3每条记录最多尝试的次数
StuckAfter00:10:00发送中超过这么久没有结果即视为进程中断，改回排队中
Telegram:MaxDispatchConcurrency16全部机器人共用的同时处理上限
Telegram:DedupLifetime00:30:00消息去重标记的保留时长
Telegram:PollingTimeoutSeconds50长轮询每次等待的秒数（不配 Webhook 时用长轮询）
Telegram:Texts:*见 appsettings.json回复文案；写成空串即不发该条回复，{botUsername}、{chatId}、{userId} 会被替换
Telegram:Retry:MaxRetries3出站调用 Bot API 失败后最多再试的次数
Telegram:Retry:BaseDelayMs / MaxDelayMs500 / 10000退避：第 n 次等 min(MaxDelayMs, BaseDelayMs × 2^(n-1))
Telegram:Retry:MaxRetryAfterSeconds60429 的 retry_after 最多等多少秒，超过即按失败处理
Telegram:Retry:NotifyAdminOnFinalFailuretrue最终失败时私发管理员告警

机器人、Webhook 与代理在系统参数 notification.telegram 里配。

BasicApp:Realtime:SignalR ​

SignalR 的 Hub 参数，对全部 Hub 生效；缺省即 ASP.NET Core 的缺省值，不配即可。配置写错启动即失败。

键缺省说明
EnableDetailedErrorsfalse把详细错误发给客户端，生产环境不要打开
KeepAliveInterval00:00:15服务端发保活消息的间隔
ClientTimeoutInterval00:00:30多久没收到客户端的消息算断开，一般设成客户端保活间隔的两倍
HandshakeTimeout00:00:15握手的超时
MaximumReceiveMessageSize32768单条入站消息的大小上限（字节）
StreamBufferCapacity10流式调用的缓冲容量
MaximumParallelInvocationsPerClient1每个客户端的最大并行调用数

时长写 hh:mm:ss（可带天数 d.hh:mm:ss），必须大于零；只写 15 或 00:15 都算写错。数字必须是正整数。前端用 SignalR 客户端的缺省超时（30 秒没收到服务端消息即断开），把 KeepAliveInterval 调到 30 秒以上会让浏览器不断掉线重连。

签名开放接口与 OAuth 2.0 / OIDC 授权服务。这一节写错不报错：数字超出范围时夹到范围内。

键缺省说明
TimestampToleranceSeconds300签名请求的时间戳与服务端时间的最大偏差（30–3600）；随机串保留它的两倍
MaxRequestBodyBytes2097152（2 MiB）开放接口请求体上限（1 KiB–64 MiB）

键缺省说明

EnableGenerateToProjectfalse（Development 为 true）允许「生成到项目」（直接写进后端与前端源码目录）；打开了也只在 Development 生效

前端 .env ​

Vite 按模式叠加读取，后者覆盖前者：

文件入库用途
.env是各环境共用：首页与通知 Hub
.env.development是pnpm dev：开发服务器端口与代理目标
.env.production是pnpm build：接口地址（缺省同源）、路由模式与部署子路径
.env.local / .env.<模式>.local否本机改动
.env.example是全部变量与说明

前后端不同源部署时，在 .env.production 写后端地址（VITE_API_BASE_URL），并在后端 BasicApp:Cors 的 AllowedOrigins 列出前端的来源。

变量缺省说明
VITE_PORT9100开发服务器端口
VITE_DEV_PROXY_TARGEThttp://localhost:9710开发代理目标，即后端的 Kestrel:Endpoints:Http
VITE_API_BASE_URL空（同源）构建期 API 源
VITE_HOME_PATH/workbench/dashboard首页（固定首页标签、守卫兜底）；关掉工作台模块时留空，登录后落到第一个有权限的页面
VITE_ROUTER_HISTORYhashhistory 需要静态托管把未知路径回退到 index.html
VITE_BASE/部署子路径
VITE_REALTIME_HUB/hubs/notification通知 Hub 路径；留空即不建实时连接（强制下线、站内通知、跨端设置同步都不再实时）
VITE_APP_TITLE / VITE_APP_SUBTITLE / VITE_APP_DESCRIPTION / VITE_APP_LOGO空登录页品牌区；留空取应用名文案与 /favicon.png
