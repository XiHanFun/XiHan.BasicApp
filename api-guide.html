接口对接指南 ​

本页说明如何通过 HTTP 调用后端接口，适用于前端以外的对接方与集成开发者。接口全部来自后端登记的操作（[Operation("<资源>.<动词>")]），一个操作同时是 HTTP 端点，并可按需发布为 gRPC 方法与 MCP 工具。编写操作见后端开发流程。

基址与在线文档 ​

地址内容
/api/全部操作，前缀由 XiHan:Protocols:Http:RoutePrefix 决定
/openapi.jsonOpenAPI 3.1 全量文档，带 x-tagGroups（Development 缺省打开，见 BasicApp:ApiDocs:Enabled）
/openapi/<组名>.json按包分组的文档：identity、access、tenancy、organization、settings、files、notification、auditing、maintenance、openplatform、printing、chat、workflow、codegeneration、ai
/scalar交互式文档，下拉切换全量与各组
/operations.proto由同一份操作 Schema 生成的 gRPC 定义（只含 Expose.Grpc 的操作）
/mcpMCP 端点，见 MCP Server
/应用名、版本与运行环境

文档的摘要与说明按 Accept-Language 本地化，每个操作带它要求的权限码（x-xihan-permission）或策略（x-xihan-policy）。全部操作可以用 dotnet run --project backend/src/XiHan.BasicApp.Host -- operations 列出。

路由推导 ​

路由由操作 ID 推导：

操作HTTP说明
users.createPOST /api/users成功 201
users.getGET /api/users/{id}请求带 id 即实例级
users.updatePUT /api/users/{id}单例资源（请求不带 id）是 PUT /api/<资源>
users.deleteDELETE /api/users?ids=…&ids=…批量，ID 在查询串
users.listPOST /api/users:list带分页对象（嵌套）即 POST；没有分页对象的 list 是 GET /api/<资源>
users.lockPOST /api/users:lock集合级动词，请求体 { "ids": [...] }
users.reset-passwordPOST /api/users/{id}:reset-password实例级动词
departments.treeGET /api/departments:tree声明只读、没有嵌套对象即 GET，字段走查询串
profile.getGET /api/profile单例资源

请求载荷 = 路由值 ∪ JSON 请求体 ∪ 查询串，合并成一个对象；同名时路由值优先。不确定时以 /openapi.json 或前端生成的 packages/contracts/operations.ts 为准。

响应 ​

成功响应 ​

正文就是响应 DTO（application/json）。create 返回 201，其余 200。

  • 主键是 UUID v7 字符串；租户 ID 是字符串（文法 ^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$）。
  • 时间一律 UTC，ISO 8601 带 Z；按用户时区显示是客户端的事。
  • 枚举序列化为字符串（如 "Active"）。
  • 属性名 camelCase。

失败响应（RFC 9457） ​

http
HTTP/1.1 409 Conflict
Content-Type: application/problem+json
Content-Language: zh-CN

{
  "type": "urn:xihan:error:SETTINGS_CONFLICT_001",
  "title": "CONFLICT",
  "status": 409,
  "code": "SETTINGS_CONFLICT_001",
  "detail": "参数键 site.name 已存在。",
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
  "details": { "key": "site.name" }
}

错误码文法 <包>_<KIND>_<NNN>，KIND 决定状态码：

KINDHTTP典型场景
VALIDATION400请求不合法；带字段级 errors
DENIED403（SECURITY_DENIED_001 / 003 为 401）无权限、锁屏、账号停用；未认证 / 令牌无效
NOTFOUND404找不到
CONFLICT409重复、状态不允许
UNAVAILABLE503节流、维护、外部服务不可用（可能带 details.retryAfter）
TIMEOUT / CANCELLED504 / 408截止时间到、调用取消
其他500未预期

字段级错误：

json
{
  "code": "KERNEL_VALIDATION_003",
  "status": 400,
  "errors": {
    "userName": ["长度必须在 1 到 64 之间。"],
    "lines[0].sku": ["不能为空。"]
  }
}

客户端只依赖 code 与 errors：detail 已按 Accept-Language 本地化，可以直接展示，但不要拿它做分支。

请求头 ​

头说明
Authorization: Bearer <访问令牌>匿名操作（登录、验证码、刷新等）不带
Accept-Language错误文案与文档的区域，如 zh-CN
traceparentW3C Trace Context，建议每个请求生成；失败响应的 traceId 与它对应
xihan-deadline可选，RFC 3339 UTC 截止时间

租户不能由客户端自报：没有 X-Tenant-Id 头，也不认查询串或 baggage 头，租户来自令牌的 tenant 声明。

获取令牌 ​

端点 ​

操作HTTP认证
auth.login-configGET /api/auth:login-config匿名：登录方式、第三方提供方、是否要验证码
auth.captchaPOST /api/auth:captcha匿名：SVG 图形验证码
auth.loginPOST /api/auth:login匿名：密码登录
auth.send-login-code / auth.login-by-codePOST /api/auth:send-login-code / :login-by-code匿名：邮箱 / 手机验证码登录
auth.verify-two-factor / auth.send-two-factor-codePOST /api/auth:verify-two-factor / :send-two-factor-code匿名：双因素第二步
auth.refreshPOST /api/auth:refresh匿名：刷新令牌轮换
auth.me / auth.permissionsGET /api/auth:me / :permissions登录：当前用户 / 权限码、角色、菜单树、页面码
auth.switch-tenantPOST /api/auth:switch-tenant登录：换到成员租户或平台
auth.lock / auth.unlockPOST /api/auth:lock / :unlock登录：锁屏
auth.logoutPOST /api/auth:logout登录：吊销当前会话

另有 auth.register（自助注册，缺省关）、auth.request-password-reset / auth.reset-password（找回密码）、auth.external-login（第三方登录换令牌）、auth.session-roles / auth.activate-roles（会话角色激活）。

第 1 步：登录 ​

bash
curl -X POST http://localhost:9710/api/auth:login \
  -H 'Content-Type: application/json' -H 'Accept-Language: zh-CN' \
  -d '{"userName":"superadmin","password":"<密码>","captchaId":"<标识>","captchaCode":"<码>"}'
  • 平台账号不填 tenant；租户账号填注册地租户 ID。
  • 开了双因素的账号返回 {"token": null, "twoFactor": {"ticket": "…", "methods": [...], …}}，再用 auth.verify-two-factor 凭票据与码换令牌。
  • 成功返回 token：accessToken（HS256 JWT，缺省 120 分钟）、refreshToken（不透明，缺省 7 天）、sessionId、tenantId（平台账号为 null）、mustChangePassword 与用户资料。

第 2 步：携带令牌调用 ​

bash
curl -X POST http://localhost:9710/api/roles:list \
  -H 'Authorization: Bearer <访问令牌>' -H 'Content-Type: application/json' \
  -d '{"page":{"index":1,"size":20},"keyword":"admin"}'

访问令牌的声明：sub = 用户 ID、tenant = 当前租户（平台主体没有）、sid = 会话 ID、role = 本会话激活的角色 ID、模仿会话另有 act。

第 3 步：令牌过期 ​

code含义处理
SECURITY_DENIED_001（401）未认证用刷新令牌调 auth.refresh 一次并重放；刷新也失败即回登录
SECURITY_DENIED_003（401）令牌过期、签名不符、格式错同上
IDENTITY_DENIED_001会话已吊销（注销、改密、锁定、被强制下线）直接回登录，不要刷新
IDENTITY_DENIED_002会话已锁定（details.reason：ScreenLock 锁屏、PasswordChangeRequired 强制改密）锁屏用 auth.unlock 解锁；强制改密用 profile.change-password 改完即解开

刷新令牌每次轮换，旧的立即失效；并发请求要串行化刷新。

第 4 步：切换租户 ​

auth.switch-tenant 续用同一个会话（sid 不变）、轮换刷新令牌、按新租户重算角色，返回新的令牌对。客户端换令牌后整页重载，不要在旧页面状态上继续操作。只能切到注册地租户、生效中的成员租户（含运维支持）或平台；模仿态的会话不能切换。

分页、筛选与批量 ​

分页查询 ​

json
{
  "page": { "index": 1, "size": 20 },
  "filters": [
    { "field": "status", "operator": "in", "value": "Active,Locked" },
    { "field": "createdAt", "operator": "ge", "value": "2026-10-01T00:00:00Z" }
  ],
  "keyword": "zhang",
  "sorts": [{ "field": "createdAt", "descending": true }]
}
  • page.index 1–100000，size 1–500；越界是 400 KERNEL_VALIDATION_003，字段错误（errors["page.index"]）按 Accept-Language 给文案。filters 最多 32 条、sorts 最多 8 条。
  • 运算符只有 eq、ne、contains、gt、ge、lt、le、in；每个操作只接受白名单里的字段与运算符，其余给 VALIDATION 错误。
  • 受字段安全保护的字段不能筛选或排序（如 IDENTITY_DENIED_011）。

响应：

json
{ "items": [ … ], "total": 128, "page": { "index": 1, "size": 20 } }

批量写操作 ​

删除、启停、锁定、撤销一类按标识的写操作只有批量形态，单条是一元集合。删除的 ID 走查询串 ids，其余批量动词是 POST、请求体 { "ids": [...] }（不接受顶层数组）。响应是逐项结果：

json
{ "succeeded": ["0193…"], "failed": [{ "id": "0193…", "code": "IDENTITY_CONFLICT_002", "message": "不能对自己的账号执行该操作。" }] }

部分失败时 HTTP 仍是 200，逐项看 failed。message 已按 Accept-Language 本地化，可直接显示；程序分支看 code。

文件上传与下载 ​

只有 JSON 能进操作；文件走宿主的普通端点，它们同样在 openapi.json 里：

端点说明
POST /api/files/uploadmultipart/form-data 上传，返回与 files.get 相同的响应
GET /api/files/{id}/content按身份读取内容，支持 Range
POST /api/profile/avatar上传头像（只要求登录，JPEG / PNG，≤ 2 MB）
POST /api/chat-messages/attachments聊天附件上传（聊天模块开着时）
GET /api/codegen-histories/{id}/package代码生成产物包下载（代码生成模块开着时）
files.presignGET /api/files/{id}:presign，换限时签名地址（本地存储走 /blobs，S3 兼容存储直连）
files.start-upload → sign-upload-parts → complete-upload大文件分片直传

开放接口：签名调用（无 JWT） ​

服务端到服务端的调用走签名开放接口（open.* 操作），凭证在个人中心「开放接口凭证」里申请。

请求头 ​

头必需说明
X-Access-Key是AppKey
X-Timestamp是Unix 秒，与服务端相差不超过 BasicApp:OpenPlatform:TimestampToleranceSeconds（缺省 300）
X-Nonce是随机串，防重放
X-Content-Sign是请求体明文的 SHA256（或 SHA512）小写十六进制；空体即空串的散列，GET 也要带
X-Signature是请求签名（十六进制或 Base64）
X-Sign-Algorithm否须与凭证设置一致（HMAC-SHA256 / HMAC-SHA512）
X-Content-Sign-Algorithm否SHA256（缺省）或 SHA512
X-Encrypt-Algorithm / X-Encrypt-Iv否请求体加密 AES-CBC，明文不必带
X-Encrypt-Response否要求加密响应

签名算法 ​

text
规范串 = 方法大写 \n 路径 \n 规范查询串 \n 内容签名 \n X-Timestamp 原文 \n X-Nonce
签名   = HMAC(凭证密钥的 UTF-8 字节, 规范串)

规范查询串：键按序数排序、同键的值也排序，键与值都做百分号编码，用 & 连接，没有值写 key=。加密为 AES-CBC + PKCS7，密钥是凭证密钥的 UTF-8 字节（正好 16 / 24 / 32 字节直接用，否则取 SHA256）。验签失败按类别返回 400 / 403 / 409，每次调用都记开放接口日志。

自测端点 ​

操作HTTP说明
open.pingGET /api/open:ping验签自检，返回 AppKey、归属人与服务端时间（可用来对时）
open.echoPOST /api/open:echo原样回显请求体，检查加解密

OAuth 2.0 / OIDC 服务端（/api/oauth2/*）见开放平台。

实时通信（SignalR） ​

Hub服务端推送的方法
/hubs/notificationForceLogout（会话被吊销，客户端回登录）、ReceiveNotification（新的站内通知）、TaskProgress（导出等后台任务进度）、UserSettingChanged（个人设置在其他设备上改了）
