# 为什么是 6.0

## 30 秒结论

XiHan.Framework 5 换了一整套写法：能力包（`IFeature` + 清单）、操作契约（一方法一操作）、管道阶段中间件、RFC 9457 错误、按操作 ID 推导的路由。5.x 的 BasicApp 建立在 4.x 框架的 Dynamic API、Castle 拦截与约定扫描之上，「搬」到 5.0 只会得到一层层垫片。所以 6.0 选择**重写**：功能与 5.x 对齐，结构与框架同形，用同样量级的工作换一个没有兼容层的代码库。

## 一、为什么重写而不是迁移

框架侧已经把「机械迁移」跑过一遍，结论直接拿来用：

1. **迁移产物不是 5.0 的样子。** 迁移工具把每个 Dynamic API 方法包成一个「委托式操作类」，权限码仍是冒号形式、按名转调旧的权限检查器、`ICurrentUser` 靠兼容包装。能跑，但每一层都是垫片，框架随后撤掉了这套规则集。
2. **四个难题在重写时不存在。** 权限码文法、路由与响应信封、`tenant_id` / `row_version` 的列类型、平台行的可见性语义，都是从 4.x 结构倒推出来的问题；从零设计时它们是起点而不是障碍。
3. **5.0 删掉的不只是写法。** SignalR、模板引擎、升级编排、机器人渠道、签名 / 加密中间件、国内 OAuth 扫码，框架明确不再包装。迁移要逐处「承接」，重写时它们就是 BasicApp 自己的能力包。
4. **5.x 自身的债一并清掉。** 空壳的工作台查询、只实现了 SSD 的约束规则、没有写入口的会话角色激活、组件路径命名混用、手写的 70 个壳层 URL、上千处裸 px 白名单。

## 二、五个决定性选择

| # | 选择 | 理由 |
| --- | --- | --- |
| D1 | 能力包 + 操作契约；HTTP 路由由操作 ID 推导，错误用 RFC 9457，成功无信封 | 这是 5.0 唯一的一等公民写法；一份契约同时得到 HTTP / gRPC / OpenAPI / MCP / AI 工具 |
| D2 | 5.x 的 Saas 巨石拆成能力包 + Host，按 Tier 0–3 单向依赖 | 每个包自带实体、操作、权限、页面、种子、文案与测试，层级由架构测试守护 |
| D3 | 主键 UUID v7；租户 ID 是字符串；平台数据不实现 `IMultiTenant`；时间统一 UTC `DateTimeOffset` | 5.0 仓储对 `IMultiTenant` 严格相等过滤，「`TenantId = 0` 表示平台」不再成立；UUID 消掉前端的数字字符串换算 |
| D4 | 权限码 `<包>.<资源>.<动作>`，操作 ID `<资源>.<动词>`，按钮即操作 | 权限目录从操作登记派生，不再有两处维护的权限码与按钮码 |
| D5 | 前端 API 层由 `/openapi.json` 生成，错误按 `code` 分支 | 契约漂移由生成器与 CI 拦截，不靠手工同步 |

完整的全局决定与拍板记录在仓库的 `nextdocs/下一代总体方案.md` 第 4、10 节。

## 三、你会得到什么

- **装配显式**：没有约定扫描、没有 `IScopedDependency`、没有拦截器；服务在 `IFeature.Configure` 里登记，横切逻辑是管道阶段中间件。读代码就能知道一个请求经过了什么。
- **一个事实源**：权限目录来自操作登记，菜单来自页面登记，前端类型来自 OpenAPI，枚举文案来自后端消息目录。
- **失败是值**：可恢复的失败返回 `Result` / `Error`，不抛业务异常；错误码 `<包>_<KIND>_<NNN>` 决定 HTTP 状态与 gRPC 状态。
- **默认收紧**：每个操作显式写 `Expose`（编译期诊断 `XHG004` 强制），管理操作只走 HTTP，选中的只读操作才进 MCP / AI；权限码缺省要求认证。
- **文案不进代码**：每个包一个消息常量类 + 10 种区域的 JSON，错误只带键与参数，由宿主按 `Accept-Language` 翻译。

## 四、代价与边界

- **不做数据迁移**：6.0 的主键、列类型、权限码、表名全变，不提供 5.x → 6.0 的迁移工具。要换到 6.0 的部署在 6.0 上重录租户与账号，5.x 部署留在 `release/v5` / `hotfix/v5` 维护线。
- **不做协议兼容**：不提供 5.x HTTP API 的兼容层或双协议并行，对接方需要按[接口对接指南](./api-guide)改造。
- **Native AOT 不是目标**：SqlSugar、MailKit、Scriban 等不是 AOT 包；但操作登记按框架要求使用源生成的 `JsonSerializerContext`。
- **仍在预览**：N3（工作流、打印、代码生成、聊天）与 N4（AI）尚未实现，现在评估 6.0 应以[功能清单](./features)里「已落地」的部分为准。
