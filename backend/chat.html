在线聊天 ​

本页说明在线聊天的会话与消息规则、语音与视频通话、推送、附件、部门群同步、聊天审计、策略参数与保留清理，适用于后端与前端开发者。

Chat 是 Tier 3 的可选模块：单聊、群聊、部门群与 AI 助手会话，消息的发送、撤回、编辑、回应、置顶、转发、已读与提及，语音与视频通话（单聊里一对一，群聊与部门群里多人，可以共享屏幕），聊天 Hub 与聊天审计。

数据 ​

六张租户库表（TenantScoped*），平台一侧以 platform 为租户落在同一张表里，平台账号之间同样能聊天；独立库的租户在自己的库里。

表说明
sys_chat_conversation会话：类型（单聊、群聊、部门群、助手）、名称、头像、单聊唯一键、部门、群主、助手、成员数、最大消息序号、最后消息、公告、描述；软删除（解散群即软删除它），不进差异日志
sys_chat_conversation_member成员：角色（群主、管理员、成员）、未读数、已读到的消息与序号、免打扰、置顶、隐藏（隐藏时会话的最大消息序号）、禁言、入会时间；退群、移出与解散群即软删除
sys_chat_message消息：会话内序号、发送人与名字快照、类型、正文、附件（JSON）、撤回、编辑、回复快照、提及（点名的成员与提及所有人）、置顶；不软删除，按保留期物理删除
sys_chat_message_reaction表情回应：同一消息、同一用户、同一表情只有一条
sys_chat_call通话：会话、发起人、媒体（语音、视频）、状态、结束的原因、响铃到几时、接通与结束时间、通话记录消息；不进差异日志
sys_chat_call_participant通话的参与者：状态（受邀、已加入、已拒绝、未接听、已离开）、加入与离开时间；同一通话里一个用户只有一行

会话内的消息按序号排序：发消息时对会话行加一取得序号（行锁让同一会话的发送串行），历史的游标、已读位与已读回执都比序号。主键是 GUIDv7，同一毫秒内没有先后，不能用来排序。

规则 ​

规则说明
单聊同一对用户每侧只有一个，没有即建；不能和自己单聊
群聊含群主至少两人，发起人为群主；加人、移出、改信息与公告、禁言要群主或管理员，转让群主、设管理员与解散只有群主；群主不能退群或被移出，只能转让或解散
解散群只在群聊（CHAT_VALIDATION_003）、只有群主（CHAT_DENIED_003）。里面还没结束的通话先结束（还没人接的记已取消，通话中的以中断结束），追加一条解散提示，再把会话与它的全部成员行一起软删除：谁的会话列表里都不再有它，之后在里面做什么都当它不存在（CHAT_NOTFOUND_001，查历史这类先核对成员的是 CHAT_DENIED_001）。消息留着、保留清理照常，聊天审计照样看得到；解散不能撤销
部门群只有本部门的成员能进，打开时补齐部门现有成员；没有群主与管理员，所以没人能改信息、置顶消息或禁言；名称随部门、不能改；平台没有部门，部门群只在租户一侧
成员范围加进会话的人必须属于当前一侧：平台是注册在平台的账号，租户是注册在本租户的用户与租户成员（CHAT_VALIDATION_021）
发送只有成员、没被禁言；文本必填不超过 4000 个字符，图片与文件至少一个附件（可带说明），语音恰好一个附件、1 到 60 秒、没有正文；系统提示、助手回复、通话记录与聊天记录只由服务端追加
提及与回复最多提及 20 名成员；提及所有人（mentionAll）只有群聊的群主与管理员能用（CHAT_DENIED_002），单聊、助手会话与部门群用不了（CHAT_VALIDATION_033，部门群没有群主与管理员）；只能回复本会话未撤回的消息，存「发送人: 内容」快照
撤回本人、发出 2 分钟内，清空正文、保留行与附件；通话记录不能撤回
编辑本人的文本、发出 5 分钟内、没被禁言
置顶消息单聊双方都能，群与部门群只有群主与管理员，每会话最多 10 条（CHAT_CONFLICT_001）
转发在服务端做：同一个会话里的一条或多条（最多 50 条，不同会话的不能一起转，CHAT_VALIDATION_034）转到一个或多个会话。逐条转发按原来的先后原样复制类型、正文与附件，不带转发来源，助手回复按文本转出；合并转发（merge）收成一条聊天记录。系统提示、通话记录与已撤回的不能转发（CHAT_VALIDATION_022），不是成员或被禁言的会话逐项失败
聊天记录合并转发出来的一条类型为 Record 的消息：发送人是转发的人，正文是 JSON（sourceType、sourceName、participants、items，每条带发送人、原来的时间、类型、正文与附件），附件列是里面所有消息的附件，目标会话的成员凭它换得到下载地址；会话预览写「[聊天记录]」。它能再被转发、再被合并（套在里面），不进会话内搜索；正文超过 50 万个字符即拒绝（CHAT_VALIDATION_035）
已读未读清零、已读位前移（不回退，没给消息即读到最新），已读位推给全体成员

系统提示（建群、邀请、退群、移出、转让）与会话预览按发起调用的区域写进库里，公告以操作人的身份进消息流。

前端在消息的右键菜单里进多选：勾选能转发的消息（系统提示、通话记录与已撤回的选不了），输入区换成操作条，逐条或合并转发到选中的会话；聊天记录在消息流里是一张卡片（标题、前几行、条数），点开按原来的先后列出里面的消息，套着的聊天记录能再点进去。群主与管理员在群聊的提及列表里多一项「所有人」，收到的人会话列表里出「有人@我」、气泡高亮。

消息只带被提及的用户 ID，正文里的「@名字」由前端按会话成员名单对上：对得上的可以点，打开那个人的资料卡；改过名或已不在群里的照普通文字显示。回复的引用块点了定位到被回复的那条：它就在眼前这一段里直接滚过去，不在就以它为中心重载；定位到的消息（引用块、搜索命中、置顶都一样）整行铺一条底色、几秒后撤掉，原消息已被保留期清理的提示一声。

附件可以点按钮选、从剪贴板粘贴，或把文件拖到消息流上，都先暂存在输入区、发送时才上传。文件消息里浏览器通常放得了的视频（按扩展名认：mp4、m4v、mov、webm、ogv）在气泡里就地播放：点了封面才换签名地址、开始取流，地址放到一半过期就换一个接着放，浏览器解不了的退回按普通文件显示。同一时刻只有一段语音或视频出声。

别人发来消息时的提醒：不在看这个会话时响提示音（与站内通知的音不同），不在聊天页时上灵动岛；页面看不到（窗口最小化、切到别的标签页或被别的窗口整个挡住）时另发系统通知，看得到时不发（窗口没有焦点也一样）（单聊是「对方 / 内容」，群里是「群名 / 谁: 内容」，同一个会话只留最新一条，后一条照样弹出），点了回到那个会话。系统通知由偏好设置的「桌面通知」控制，缺省开，浏览器的授权在进入页面后的第一下操作时询问一次。免打扰的会话都不提醒，未读照记。未读合计（不含免打扰的会话）还写在页面标题前面。

助手会话 ​

一个用户对一个助手只有一个会话，打开时没有即建并发开场白。助手不是成员，不算未读，助手会话也不显示已读回执。回复是前端发出用户消息之后单独发起的调用：

  1. 前端发出提问，再调 chat-messages.reply-assistant，带自己生成的 replyId。
  2. 服务端从库里取最近的提问与回复，经 Contracts 的 IChatAssistants 流式生成。Chat 不引用 AI，AI 关掉时没有实现，三个助手操作（chat-conversations.assistants、open-assistant、chat-messages.reply-assistant）返回 503 CHAT_UNAVAILABLE_001，聊天其余功能照常。
  3. 生成期间这次调用还没开事务，增量经立即推送发给本人（ChatAssistantDelta）。
  4. 结束后过敏感词（与用户输入同一套），落库为一条助手消息（超过 20000 个字符截断），提交之后按普通消息推送，再推 ChatAssistantCompleted。

失败（模型不可达、空输出、敏感词、提示词停用、检索失败）时不留消息，操作以 Problem Details 结束，同时立即推 ChatAssistantCompleted 带 errorCode 与 error。

错误码说明
CHAT_VALIDATION_026不是助手会话
CHAT_VALIDATION_027会话里没有可回答的提问
CHAT_UNAVAILABLE_001助手不可用（AI 没有装配）
CHAT_UNAVAILABLE_002生成失败。原因只有异常类型，完整异常看应用日志
CHAT_UNAVAILABLE_003模型没有产生任何内容

助手本身的配置见 AI 能力。

语音与视频通话 ​

单聊里是一对一通话，群聊与部门群里是多人通话，通话中可以共享屏幕。通话的媒体有三种：语音（Voice）、视频（Video）与屏幕共享（Screen）——屏幕共享是单独发起的那一种：发起人先挑要共享的画面、带着麦克风开始响铃，别人按语音进、进来就看到屏幕，人数上限与视频通话相同。媒体在浏览器之间走 WebRTC：多人通话里每两个人之间各一条连接（全互联，不经媒体服务器），能直连就直连，直连不通时经 TURN 中继；服务端只记通话的状态、转发信令，不经手也不录制媒体。

状态 ​

通话的状态说明
Ringing响铃中：发起人已加入，还没有别人进来
Ongoing通话中：有人接听或加入过
Ended已结束，带结束的原因
参与者的状态说明
Invited受邀，在响铃
Joined在通话里
Rejected拒绝了
Missed没接到：响铃到点、响铃时离线，或发起时占线、不在线没能响铃
Left离开了
结束的原因说明
Completed通话中的人陆续挂断，剩下不到两个人
Cancelled没人接之前发起人挂断，或发起人离线
Rejected受邀的人都拒绝了（响铃时受邀的人挂断也算拒绝）
Missed受邀的人都没来，其中有人没接到（响铃到点、离线，或没能响铃）
Interrupted通话中有人离线，剩下不到两个人

规则 ​

规则说明
发起单聊呼叫对方：自己与对方都不在别的通话里（受邀还没接也算占着），对方此刻在线，否则不响铃、直接拒绝。群聊与部门群点名邀请成员（inviteeUserIds）：不能为空、都得是会话成员、连发起人在内不超过人数上限；占线与不在线的受邀人不响铃、记成没接到，一个能响铃的都没有即拒绝；一个会话同一时刻只有一通。助手会话不能通话
人数上限读 chat.policy：语音 callMaxVoiceParticipants（缺省 8），视频 callMaxVideoParticipants（缺省 6）。发起时按受邀的人数核对，接听与加入时按已经在通话里的人数核对
接听与拒绝只有受邀还没答复的人、通话还没结束时；多端同时接听只有先到的成功，其余端随推送停铃。有人接听即接通，别的受邀人照常响铃
加入多人通话还没结束时会话成员都能加入（chat-calls.join）：没被邀请的、拒绝过的、没接到的、离开了的都能来；人数满了即拒绝
挂断没人接时发起人挂断即取消，受邀的人在响铃时挂断即拒绝；通话中挂断即离开，剩下不到两个人、又没人还在响铃时通话结束；已经结束的、早就不在里面的照样成功（几个人可能同时挂）
响铃到点响铃秒数读 chat.policy 的 callRingSeconds（缺省 60）。到点由端上来挂：发起端准点挂，受邀端晚 2 秒挂掉自己那份邀请；服务端把到点前 3 秒起的挂断一律记未接听
离线用户离线（过了离线宽限）即离开他占着的通话：受邀的记没接到，没人接时发起人离线即取消，通话中的记离开、剩下的人不够时以中断结束
收尾内建作业 chat.calls.sweep 每 5 分钟按平台与每个租户收一遍没人管的通话（响铃过点、发起人已离线、通话中已经离线的人与过点还挂着的邀请）；停用的租户跳过
先后同一会话里的发起、接听、拒绝、加入、挂断对会话行加锁排成先后：两个人同时互相呼叫只成一通，一个群里不会同时起两通。锁只在会话上，两个不同会话里的人在同一瞬间呼叫同一个人时可能各响一通，先接的成立，另一通到点记未接听

通话记录 ​

通话结束时往会话里追加一条类型为 Call 的消息：发送人是发起人，正文是 JSON（callId、media、reason、durationSeconds、missedUserIds），会话预览按媒体写「[语音通话]」「[视频通话]」或「[屏幕共享]」。只给没接到的人（missedUserIds）各记一条未读，接通过的、自己拒绝的与没被邀请的不记。通话记录不能撤回、不能转发，也不进会话内搜索；聊天审计里显示为「媒体 · 结果」。

信令与穿透 ​

  • 信令经聊天 Hub：占着通话的端调 CallSignal(callId, toUserId, data)，服务端核对它是这通接通了的电话里的人，把 ChatCallSignal（callId、fromUserId、data）转出去：给了 toUserId 只转给他（他也得在通话里），没给转给已经加入的其他人。data 是两端之间约定的 JSON，不超过 20000 个字符，服务端不解析、不落库：会话描述与 ICE 候选指给一个人，麦克风、摄像头与屏幕共享的开关发给所有人。
  • 通话每次变化推 ChatCallChanged，载荷是通话此刻的样子，发给参与过这通电话的每个人的全部连接；多人通话另发给正开着这个会话的连接（会话组），没被邀请的成员据此看到有通话在进行。打开会话时用 chat-calls.ongoing 取这个会话里还没结束的那一通。
  • 穿透服务器由 chat-calls.ice-servers 给出，取自宿主配置 BasicApp:Chat:Calls（见配置）。TURN 用共享密钥的限时凭据：用户名是「到期秒数:用户」，凭据是它的 HMAC-SHA1，按调用方现签，密钥不下发。都不配也能用，只是只有同一网段或能直连的两端打得通。

媒体连接与屏幕共享 ​

  • 通话里每两个人之间一条连接，后加入通话的一方出 offer（同一毫秒加入的比用户 ID），两端各自按同一份参与者算，不会同时出。有人离开只关与他的那条，他再加入时重新建。
  • 每条连接在协商时按固定次序留好三个轨道位：麦克风、摄像头、屏幕。之后开关摄像头、换设备、开始与停止共享屏幕都只是往位上换轨道，不重新协商；对端凭位置认出是哪一路。
  • 屏幕共享在哪种通话里都能开：浏览器让用户挑整个屏幕、一个窗口或一个标签页，只共享画面、不带系统声音；从浏览器自己的「停止共享」上停掉也算停止。不支持的浏览器（多数手机浏览器）不出这个按钮。
  • 单独发起屏幕共享（会话头的第三颗钮，媒体 Screen）时先挑画面再呼叫，在选择框里取消就不打；挑好的画面一发起就放在屏幕位上，接听与中途加入的人建连接时直接拿到。发起人停止共享后通话照旧，谁都可以再共享。
  • 全互联里每个人要给其余每个人各发一路媒体，上行带宽随人数增长，人数上限按此定；人更多要换成经媒体服务器转发的架构。

前端 ​

  • 会话头有语音与视频按钮：单聊直接呼叫对方；群聊与部门群先开点名的对话框，列出会话成员，不在线的选不了，最多选到人数上限减一。通话记录的气泡可点，用同样的媒体再打一次。
  • 群里有通话在进行时，会话顶上出一条横幅（谁发起的、几个人在里面），没在里面的成员点「加入」即进通话；自己已经在别处接听的只显示提示。
  • 来电卡片与通话窗挂在布局根部：任何页面都能接听，离开聊天页通话不断。多人通话的来电写明是哪个群。通话窗可拖动、收拢成标题栏或铺满视口，里面一人一格（还在响铃的也占一格，连不上的标出来），有人共享屏幕时屏幕占主画面、各人收成底下一排；有静音、关摄像头、共享屏幕、换麦克风与摄像头（浏览器支持时还有扬声器）与挂断。
  • 来电响铃声，打出去等对方接听时响回铃，都是连着响的长音，直到接通、挂断或响铃到点；页面看不到时来电另发一条挂着不消失的系统通知（谁打来、什么通话），来电有了结果即收起。
  • 来电在每个开着的页签都响；只有发起、接听或加入的那个页签建媒体连接、处理信令，别的页签随推送停铃。没有 chat.chat-calls.call 的人不出来电卡片，那份邀请到点记没接到。
  • 与一个人之间 30 秒媒体还没连上、或连接断开 8 秒没恢复，这条连接作废、他那一格标成连不上；与所有人都这样了，端上自己挂断并提示。
  • 响应与推送之间没有先后：接听、加入的请求在路上时到过推送的，以推送为准，不拿可能更旧的响应对齐连接。
  • 刷新页面：还在等自己答复的来电经 chat-calls.active 认回来；刷新之前占着通话的那个页签，媒体已经随页面没了，回来后替自己挂断（多人通话里别人照常，可以从横幅再加入）。
  • 浏览器只在 HTTPS 与 localhost 下给麦克风、摄像头与屏幕。

选人 ​

chat-conversations.user-options 供发起单聊、建群与加成员：列出当前一侧的正常账号（范围同上面的「成员范围」），只要会话读权限，不要身份的用户读权限与组织的归属读权限。

参数说明
keyword匹配用户名与显示名
departmentId只看这个部门及其全部下级里任职的人；平台没有部门
skip、limit按显示名排序逐页取，limit 缺省 50、最大 500

响应的 hasMore 说明后面还有没有；每个人带头像文件与主部门的名称（没有任职或在平台一侧为空）。会话成员（members）同样带头像文件。

前端的选人是可勾选的候选列表：可搜索、可只看最近联系人（取自单聊会话）或按部门筛选，往下逐页加载；多选时旁边列出已选的人，换一批候选也留着。加成员时已在群里的人照样列出、标注而不可选。会话的资料、公告、个人设置（置顶、免打扰）与成员治理都在会话详情里：宽屏是消息流旁边的第三栏，放不下时顶替消息流。

会话列表的右键菜单可以置顶、免打扰或隐藏会话。隐藏（chat-conversations.hide）只从自己的列表里拿掉，置顶、免打扰与未读都不动，未读也不计入角标；服务端记下隐藏时会话的最大消息序号，之后来了新消息（别人或自己在别的端发的、系统提示、通话记录都算）会话自己回到列表，发消息不用为它多写一笔。会话列表照样返回隐藏的会话、带 isHidden：前端按名字搜得到，从搜索、资料卡里共同的群或发起单聊再打开即回到列表；转发的会话与选人的最近联系人同样只在按名字搜时列出隐藏的。

搜索、图片与文件、资料 ​

操作说明
chat-messages.search在一个会话里按关键字找（匹配正文与附件名），只有成员能搜；最近的在前，beforeMessageId 往前翻页
chat-messages.search-all在调用方所在的全部会话里按关键字找，口径同上；最近的在前，结果跨着会话、没有共同的序号，按偏移翻页（skip 最大 10000，take 缺省 20、最大 50），翻页之间来了新消息会错开一两条
chat-messages.media一个会话里发过的图片（kind=Image）或文件（kind=File）消息，只有成员能看（CHAT_DENIED_001）；最近的在前，beforeMessageId 往前翻页，take 缺省 30、最大 100。聊天记录里套着的附件不在这里
chat-conversations.user-profile聊天里看一个人的资料：用户名、显示名、头像、主部门、在不在线，与两个人都在的群聊与部门群（按群名排，单聊与助手会话不算，看自己时为空）。那个人须属于当前一侧（CHAT_VALIDATION_021），不存在是 CHAT_NOTFOUND_003；只要会话读权限，不要身份的用户读权限

搜索都不算已撤回的消息、通话记录与聊天记录，关键字为空返回空；图片与文件同样不列已撤回的。三个列表的响应都带 hasMore。

前端会话列表的搜索框同时找会话与聊天记录：上面是名字匹配的会话，下面是聊天记录里的命中（哪个会话、谁说的、说了什么），点了打开那个会话并定位到那条消息。会话详情里的「图片与文件」把会话里发过的图片与文件分开列出、逐页往下取：图片点开是这一组的看片浮层，文件点了下载、另能定位到它所在的那条消息。消息流里点别人的头像、头像右键菜单的「查看资料」、会话详情里点成员的头像都打开同一张资料卡，从卡上能发消息、打语音或视频（对方在线时），也能进共同的群。

推送 ​

聊天 Hub /hubs/chat 由 Chat 登记、宿主一并映射，认证、会话门禁与连接登记同通知 Hub（见实时推送）。推送按成员点发给会话这一侧的用户，在调用提交之后发出；配了 Redis 时跨实例。

方向方法
服务端推送ReceiveChatMessage、ChatMessageRecalled、ChatConversationChanged（12 种变更）、ChatTyping、ChatMessageEdited、ChatReactionChanged、ChatReadPositionChanged、ChatPresenceChanged、ChatAssistantDelta、ChatAssistantCompleted、ChatCallChanged、ChatCallSignal
客户端可调JoinConversation（核对成员后加入会话组）、LeaveConversation、Typing（核对成员后组播给组里的其他连接，不落库）、CallSignal（核对是接通了的通话里的人后转给指定的人或通话里的其他人，不落库）

ChatConversationChanged 的变更种类：created、member-added、member-removed、info-changed、owner-transferred、member-silenced、member-role-changed、pinned-changed、member-setting-changed、department-joined、department-kicked、removed、left、dissolved。成员少了时留下的人收到 member-removed（部门群是 department-kicked），据此重读成员；出去的那个人另收一种、只推给他本人：被移出（含随部门归属移出）是 removed，自己退群是 left——他再读这个会话只会被拒绝，前端直接把它从列表里拿掉（正开着就收起），被移出的另出一条提示说是哪个群。群被解散时推给解散那一刻还在里面的成员，前端同样把它拿掉，不是群主的另出一条提示。

在线状态 ​

在线即此刻在这一侧持有实时连接（任一 Hub 都算，见实时推送）。

  • 读的时候带当时的状态：会话列表的单聊带 peerOnline，会话成员与选人候选带 isOnline。
  • 之后的变化推 ChatPresenceChanged（userId、isOnline）：Chat 订阅 Realtime 的 basicapp.realtime.presence-changed，按处理时的在线状态推，乱序或重复投递推出去的都是当时的事实。
  • 受众是他的单聊对端（按人点发），以及正开着他所在的群或部门群的连接（会话组，即调过 JoinConversation 的连接）；不按群的全体成员扇出，没参加任何会话的人不推。
  • 刷新页面、断线重连不闪：最后一条连接断开后有一段宽限（缺省 8 秒），宽限内又连上即不推离线，只在回来时补推一次在线。

前端把读回来的状态与推来的变化记在同一处，头像右下角的绿点、单聊头部与详情里的「在线 / 离线」、群成员的在线人数都从那里取；实时连接连上时（断线重连，或会话列表在连接建好之前就读了）把会话列表与当前会话的成员重取一遍。

附件 ​

附件以会话为访问范围，经 Files 的附件契约 IAttachmentFiles 存取：上传与秒传只要聊天的发送权限，文件存在调用方这一侧、来源记 chat，大小上限与存储配额同普通上传；发送时核对附件是自己在聊天里上传的（CHAT_DENIED_009），文件名与大小以文件记录为准；会话成员经 chat-messages.presign 凭会话换签名地址，附件须出现在这个会话的消息里，或是自己上传、还没发出的文件。文件管理照旧要 files.files.read。保留清理删掉消息时，附件文件没有留存的消息再用、也不是会话头像的才一并删除（见策略与保留清理）。

群头像是文件主键或直链：给文件主键时同样须是自己在聊天里上传的（CHAT_DENIED_009），设上之后会话成员经 chat-messages.presign 凭会话换它的地址。单聊的头像是对端用户的头像。

部门群同步 ​

Organization 在加入与移出部门时记领域事件 basicapp.organization.membership-changed（随写入进发件箱），Chat 订阅它：已经建了的部门群里，进了部门即入群、移出部门即出群，并推会话变更（被移出的人也收到）。处理时按当时的归属核对，消息乱序或重复投递都只做一次；写库失败即投递失败、由消息代理重试。

聊天审计 ​

持 chat.chat-audit.read 即看当前一侧全部会话的消息与通话记录，不要求是成员：

  • 列表按关键字（正文、发送人名、附件）与会话、发送人、消息类型（含通话记录与聊天记录）、发送时间、是否撤回筛选，缺省不含已撤回的，筛选 includeRecalled 为 true 即都看；
  • 消息详情带所在会话、附件、提及（含提及所有人）、回复与表情回应；
  • 会话成员列出会话与它现在的成员；
  • 已解散的群照样查得到：消息还在（末尾是那条解散提示），会话带解散时间 dissolvedAt，成员列的是解散时还在里面的人；
  • 通话记录（chat-audit.list-calls）按发起时间倒着列出通话：所在会话、发起人、媒体、状态与结束原因、发起 / 接通 / 结束时间、时长（没接通或还没结束为空），以及每个参与者的状态与进出时间。可按会话、发起人、参与者（participantUserId）、媒体、状态（eq）、结束原因（eq / in）与发起时间（startedAt 的 ge / le）筛选，只能按发起时间排序，没有关键字；不认识的筛选、排序与关键字一律 CHAT_VALIDATION_025。媒体在浏览器之间直连、不经服务端，所以只有通话的状态可查，没有通话内容。

撤回清空的正文与编辑前的正文不另留。

前端的审计页一页两签：「消息」是消息列表、消息详情与会话成员，「通话记录」是通话列表，行上的「详情」看参与者、「成员」看所在会话的成员。

策略与保留清理 ​

参数 chat.policy（JSON，种子建好的内建参数，租户可建同键参数覆盖敏感词、响铃秒数与通话人数上限），缺省值：

json
{ "retentionDays": 365, "sensitiveWords": [], "callRingSeconds": 60, "callMaxVoiceParticipants": 8, "callMaxVideoParticipants": 6 }
字段说明
retentionDays消息与通话记录的保留天数，1 到 3650，只读平台的值
sensitiveWords敏感词，不区分大小写的包含匹配；租户建了同键参数即用租户的；管发送与编辑的正文（含图片与文件的说明），不管群名、公告与文件名（CHAT_VALIDATION_023）
callRingSeconds通话响铃秒数，10 到 300；到点没人接即未接听；租户建了同键参数即用租户的
callMaxVoiceParticipants语音通话连发起人在内的人数上限，2 到 12；租户建了同键参数即用租户的
callMaxVideoParticipants视频通话与屏幕共享连发起人在内的人数上限，2 到 8；租户建了同键参数即用租户的

JSON 不合法、保留天数、响铃秒数或人数上限越界即 CHAT_VALIDATION_024，发送、通话与清理都不按错误的值执行。前端经 chat-calls.settings 取响铃秒数与两个人数上限。

内建作业 chat.messages.cleanup 每天 04:00（UTC）按平台与每个租户逐个清理（独立库的租户清它自己的库），每批 500 条、一批一个事务：

  • 消息：取创建早于保留期的消息，先删它们的表情回应，再删消息。
  • 附件文件：这批消息挂着的文件，只要还有留存的消息（含转发与合并转发的聊天记录）挂着它，或它是某个会话的头像，就留着；其余的按文件管理的删除处理。
  • 通话：结束早于保留期的通话连同参与者删除；响铃与通话中的再老也不动。
  • 不删会话与成员。

每侧最多 200 批，没删完的下一次接着删（日志记为延后）。一批失败整批回滚，这一侧记为失败、只记日志，不影响其他侧。

开关 ​

BasicApp:Modules:Chat:Enabled（缺省开）。关掉后宿主不装配 Chat：权限目录、页面、Hub、附件上传端点、两个内建作业与部门归属、在线状态的订阅都不在，菜单不下发、操作 404；Organization 照常发出领域事件，没有订阅方。六张表仍由正式库的基线脚本建出（开发库的 InitTables 只建装配了的包的表）。
