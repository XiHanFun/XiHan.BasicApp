系统设置 ​

本页说明参数配置、字典与业务编号，适用于后端开发者与运营配置人员。

Settings 包（Tier 2）提供参数配置、字典与业务编号三类「运行时可调」的数据，并通过 Contracts 的 IConfigValueReader 与 INumberGenerator 供其他包使用。三类都是平台库实体、实现 IOwnedByTenant：平台一份，租户可以有自己的；读共享，写只在本侧。

和 appsettings 的区别

appsettings.json 的 BasicApp:* 是部署配置（改了要重启，见配置参考）；本页的参数是运营配置，存在库里、后台改了即生效，租户可以覆盖。

参数配置 ​

SysConfig：键、名称、分组、值、缺省值、数据类型、是否加密、是否内置、是否允许租户覆盖、状态、排序、说明。

规则说明
键3–128 位，创建后不可改；本侧唯一
数据类型Text、Number、Boolean、Json、Array，按类型校验值与缺省值
加密值经 ISecretProtector 加密存放，不回显（value 为空、hasValue 标出）；更新时留空即保留原值；开关加密会就地加密或解密现值
租户覆盖租户新建与平台参数同键的参数即覆盖它；平台参数 allowTenantOverride = false 时拒绝
生效值IConfigValueReader：只看启用的参数 → 当前租户的同键参数优先、其次平台的 → 值为空回落缺省值 → 加密值解密后返回

操作 configs.create / get / list / update / delete，权限 settings.configs.*（两侧）；内置参数不可删，也不能改数据类型。

内建参数 ​

读参数的包在 Configure 里 AddConfigCatalog 登记 ConfigDescriptor（键的首段是包名），种子 settings.configs 据此写成平台的内建参数：名称、分组、数据类型、缺省值、是否允许租户覆盖、是否加密与说明每次对齐（没变不写，加密与否变了即就地加密或解密现值），值、状态与排序号只首写、之后归运营；值留空，生效值即缺省值。运营先手建了同键的平台参数即收为内建，但它现有的值不符合登记的数据类型时种子报 SETTINGS_VALIDATION_002（消息带参数键）、不改它，要由人把值改对。下表的参数都由种子建好，在参数配置页直接改值；数据类型固定，JSON 与数组类型的值保存时即校验。

代码读取的参数 ​

键谁读类型含义
identity.login-methodsIdentity数组登录页开放的方式（只认平台的，不许租户覆盖）：password、email、phone、passkey（还要宿主配了 XiHan:Security:WebAuthn）；缺省 ["password"] 即只有密码登录，写错即登录配置报错
settings.siteSettingsJSON站点设置（允许租户覆盖：租户的同键参数是它的品牌，只写要改的字段）：缺省系统名 XiHan.BasicApp、版权方 XiHanFun，写错的值保存时即拒绝，见下文站点设置与租户品牌
identity.passwordIdentityJSON密码策略（只认平台的）：最短长度、须含的字符、历史深度、有效天数与强制改密，写错的值保存时即拒绝，见统一认证
identity.impersonationIdentityJSON模仿登录（租户可覆盖）：sessionMinutes 缺省 30、notifyTarget 缺省 true；写错即不能发起，见统一认证

字典 ​

SysDict + SysDictItem：字典码、名称、状态；字典项是同一字典内无环的树，带值、标签、排序、缺省项（字典内唯一，设新的即清掉旧的）与 JSON 元数据。

规则说明
字典码创建后不可改；平台新建要求全库无同码，租户新建要求平台与本租户都无同码（字典不覆盖）
可见性读共享：平台字典 + 本租户字典；租户改不了平台字典
停用停用的字典不再出现在下拉选项里
内建各包登记的字典，不能删，登记的项也不能删（SETTINGS_CONFLICT_006）
操作权限码说明
dicts.create / get / list / update / deletesettings.dicts.*管理字典
dict-items.create / get / list / tree / update / deletesettings.dict-items.*管理字典项
dicts.options登录即可业务表单的下拉（GET /api/dicts:options?code=）

dict-items.list 分页检索字典项（按 dictId 筛选某本字典，关键字匹配编码、名称与附加值），dict-items.tree 一次取整本字典的项（深度优先、带层级，同级按排序号再按编码，给上级选择与级联取值用）。dicts.list / get / options 与 dict-items.list / tree 也是 MCP / AI 工具。前端 SchemaPage 的字典列与壳层的 dictApi.options 都接在 dicts.options 上。

内建字典 ​

业务按编码依赖某本字典的包在 Configure 里 AddDictCatalog 登记 DictDescriptor（编码的首段是包名，项的上级排在下级前面、缺省项至多一个），种子 settings.dicts 据此写成平台的内建字典：字典的名称、分类、说明与登记的项（名称、附加值、上级）每次对齐，没变不写；状态、排序号与缺省项只首写，之后归运营；运营另加的项不动，照常可删。运营先手建了同码的平台字典即收为内建；租户已有同码的字典时种子报 SETTINGS_CONFLICT_002、不改它，要由人处理。目前没有包登记内建字典。

演示字典由种子 settings.demo 在演示开关打开时写入，不是内建的。

业务编号 ​

SysNumberingRule + SysNumberingAllocation：编码、前缀、分隔符、日期格式（None、Yyyy、YyyyMM、YyyyMMdd、YyMM、YyMMdd、MMdd）、流水长度、重置周期（Never、Daily、Monthly、Yearly）、时区（缺省 UTC）。

  • 发号在独立的作用域与事务里完成（StoreScope），号一经发出永久消耗、外层调用失败也不回收、允许空洞；先对规则行加锁更新，同一规则的发号由此串行，并发发号不重复。
  • 幂等键：同一幂等键参数相同即重放（isReplay），不同即 SETTINGS_CONFLICT_013。
  • 日期格式要能区分重置周期，时区要能解析，流水位数要装得下已发出的流水值。
  • 租户看得见自己的规则与平台标为「供租户使用」的规则，只能改自己的；编码在所属一侧内唯一。
操作权限码说明
numbering-rules.create / get / list / update / deletesettings.numbering-rules.*
numbering-rules.previewsettings.numbering-rules.read按格式在当前时刻拼出号码，不读库、不发号
numbering-rules.generatesettings.numbering-rules.generate发号（也可由其他包经 INumberGenerator 调用）
numbering-rules.allocationssettings.numbering-rules.read发号记录
numbering-rules.resetsettings.numbering-rules.reset重置流水，理由必填（进操作审计）

站点设置与租户品牌 ​

站点名、Logo、浏览器图标、登录页（标语与说明）与页脚（版权方、链接、起始年份、备案号与链接）存在系统参数 settings.site：平台的是站点设置，租户的同键参数是它的品牌，只写要改的字段，没写的沿用平台的；文字为空即前端用界面自带的文案。

操作 / 端点权限说明
site.get（GET /api/site）settings.site.read设置页用：平台取站点设置，租户取自己的品牌（own）与沿用的平台设置（inherited）
site.update（PUT /api/site）settings.site.update整体覆盖调用方这一侧；图片只能保留现在的或去掉（去掉的随即回收），给别的文件 ID 即 SETTINGS_VALIDATION_012
POST /api/site/assets/{slot}settings.site.update换掉 logo 或 favicon：按文件头认 PNG、JPEG、WebP 与 ICO（不认 SVG），不超过 2 MB，否则 SETTINGS_VALIDATION_013；旧图回收
site.resolve（GET /api/site:resolve?host=）匿名前端壳层用：登录了按令牌里的租户，没登录按 host 找绑定了这个域名的租户，返回生效的设置（租户的叠在平台的之上）与按域名找到的租户 ID
GET /api/site/assets/{id}匿名读站点图片（登录页在登录之前就要显示），只认经上面的端点上传的文件，按不可变内容缓存一年

邮件、短信与机器人消息模板里的变量 brand 调用方没传时，取发送这一侧生效的系统名（经 Contracts 的 ISiteBrand），租户发出的消息即带它自己的品牌。

图片与头像一样存平台侧、公开级别，不计入租户的存储配额。按域名识别租户（SysTenant.domain，平台在租户编辑里填）只用于登录页展示品牌与预填租户框，不参与身份判定：租户仍只从令牌声明解析。套餐按包放行，基础版及以上的租户才能改自己的品牌。

用户设置 ​

个人偏好不在 Settings，而在 Identity 的 SysUserSetting（用户 × 场景 Preference / Page × 键，值是 JSON）：user-settings.get / update（只要求登录）。壳层的偏好、收藏、列表的条件预设与列设置、工作台看板布局都存在这里，改了经 UserSettingChanged 推到同一用户的其他设备。

页面 ​

src/modules/settings：参数配置（租户行可「覆盖此参数」）、字典（主从两栏）、业务编号（预览与发号记录）、站点设置（平台改站点设置，租户改自己的品牌，没填的项以灰字显示沿用的平台值）。
