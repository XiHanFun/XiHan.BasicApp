工作流 ​

本页说明工作流的引擎与存储、流程定义与实例的操作和权限、组织类受理人、待办与审批中心、审批业务的接入、通知、演示流程与模块开关，适用于设计流程、接入审批的后端与前端开发者。

Workflow 是 Tier 3 的可选模块（BasicApp:Modules:Workflow:Enabled，缺省开）。引擎、定义目录与存储都是框架的工作流，本包只做管理操作、组织类受理人、待办与审批中心、审批业务接入、通知与页面。授权申请（Access）是审批业务接入的参照实现，见约束规则与审批。

引擎与存储 ​

部分做法
存储宿主恒装框架的 Workflow.Database（模块关掉也装）：定义、实例、节点实例与书签按分区落表（租户四张随租户分库、平台四张在平台库），在调用方的工作单元里随业务提交或回滚；九张表在基线 Schema/6.0.0/0001-baseline.sql 里，配置见配置参考
并发租约表 workflow_lock_record 上的实例锁；到期书签的轮询由持有 workflow.poller 领导权的节点做
分区取自当前调用：平台调用只看平台的定义与实例，租户调用只看本租户的；没有全局定义，平台建的定义租户看不到
定义格式框架的 WorkflowJson（节点 properties、transitions、variables、超时与补偿）；设计器的布局放在定义的 properties 里
事件workflow.* 事件写进调用方事务里的发件箱，提交才发出

流程定义 ​

操作权限码说明
workflow-definitions.list / getworkflow.workflow-definitions.read列表在库里按关键字（名字、显示名、说明）、名字、分类、状态与创建时间过滤分页，可按状态、名字、显示名、版本、创建时间与发布时间多列排序（排序项依次为主次，同一列只能给一次），缺省名字升序、版本降序；详情带整份 WorkflowJson
workflow-definitions.create / update.create / .update以 WorkflowJson 建草稿（版本按同名最大版本加一）、改草稿（名字与版本沿用已存的）
workflow-definitions.publish.update单条：关联了审批业务的先过业务校验，再由框架做结构校验（WORKFLOW_VALIDATION_001）：问题按路径列在字段级 errors（键是定义 JSON 里的路径，如 nodes[2].properties.Cron、transitions[0].condition，定义级的问题是 nodes；值按调用方的语言），detail 是汇总；设计器按下标标出对应的节点与连线
workflow-definitions.new-version.create以某个名字的最新版本为底复制出新草稿
workflow-definitions.disable / archive / delete.update / .update / .delete批量；停用只对已发布的，删除只删草稿
workflow-definitions.business-types / activity-types.read已登记的审批业务；设计器可放的活动（不含 Script、事件网关、补偿与外部任务），显示名与分类展示名 categoryName 按调用方的语言

关联审批业务的定义（名字等于业务码）发布前要满足：每个结束节点都写结论、结论在业务允许的范围里（缺省 approved / rejected，否则 WORKFLOW_VALIDATION_101），不能有终止节点（WORKFLOW_VALIDATION_102）。

流程实例 ​

操作权限码说明
workflow-instances.list / getworkflow.workflow-instances.read列表按关键字（标题或关联 ID）、状态、定义名、关联 ID、发起人与创建区间过滤，可按状态、定义名、标题、创建时间与结束时间多列排序，缺省创建时间降序；详情带变量、最近一次错误（出错继续的节点记下的 lastError，按调用方的语言）、节点执行历史（带状态展示名）、待恢复的等待与所用的定义
workflow-instances.start.execute发起人是调用方；按名字取最新已发布的版本
workflow-instances.cancel / terminate / retry / signal.execute取消（启用补偿时逆序补偿）、终止（不补偿）、故障重试、发信号；审批业务的实例先过改动前校验（发信号除外），不过的那一项记失败、不交给引擎
workflow-instances.suspend / resume.update挂起与恢复

控制类都是批量，逐项返回 BatchResult。BasicApp 自己的错误码在 WORKFLOW_ 前缀下从 101 起编（WORKFLOW_NOTFOUND_101 定义不存在、102 实例不存在），引擎、目录与任务服务的失败（001 段）原样返回。

受理人 ​

框架内置 User、Starter、Expression 三种规则，本包登记六种组织类规则（按编码引用，结果与实例所在一侧可见的在用账号求交，运维支持成员、停用账号收不到待办）：

规则参数解析
Role角色编码启用角色在有效期内的成员
Department部门编码启用部门的成员（不含下级）
DepartmentLeader部门编码部门负责人
Position岗位编码启用部门里任这些岗位的人
StarterLeader层级 N（1～10，缺省 1）发起人第 N 级主管：从主部门起逐级上溯，跳过停用部门、发起人自己负责的部门与重复的负责人
StarterLeaderChain最多 N 级第 1 到 N 级主管链，配 Sequential 做逐级审批

数据来自 Contracts 的组织目录（Organization 实现）与角色成员目录（Access 实现）。设计器与转办、加签选人用 workflow-assignees.users（只要登录；关键字只匹配登录名与显示名，缺省 50、至多 200 个；按 ID 回显含停用的账号）与 roles / positions / departments（workflow.workflow-assignees.read）。

待办与审批中心 ​

只要登录（不设权限码），主体一律锁定为调用方：

操作说明
tasks.list我的待办：关键字匹配任务标题、实例标题、定义名与关联 ID，按到达时间降序，带节点、发起人与审批业务；还暴露给 MCP 与智能体
tasks.complete办理：结论（缺省 approved / rejected，节点的 AllowedOutcomes 另有约定时按它）与意见；审批业务先过办理前校验，不过即待办保留；办理后实例故障照常返回并带上原因
tasks.transfer / tasks.add-assignees转办、加签：目标要是当前一侧可见的在用账号（WORKFLOW_VALIDATION_106），加签一次至多 20 人；审批业务先过改动前校验
approvals.list-done / list-cc我已审批（办理、转办、加签）、抄送我的：读审批记录，关键字匹配任务标题、实例标题与关联 ID，带实例现在的状态
approvals.list-started我发起的：只取顶层实例，关键字匹配标题与关联 ID，可按状态过滤，运行中的带等着办的节点与人
approvals.get详情按参与关系鉴权：发起人、当前受理人、办理过或被抄送过的人，或持有 workflow.workflow-instances.read，其余 403 WORKFLOW_DENIED_101；带审批业务的单据、调用方的待办与审批轨迹
approvals.withdraw发起人撤回自己运行中、挂起或故障的顶层实例（即取消），审批业务先过改动前校验，之后回调中止回写

办理、转办、加签、抄送各写一条审批记录（sys_workflow_task_record，租户库、只追加，平台一侧租户为 platform）；「我已审批」「抄送我的」与审批轨迹都读它。找不到人按策略自动通过或驳回的节点在轨迹里记为自动处理。

审批业务接入 ​

业务包在 Configure 里以 services.AddWorkflowBusiness<THandler>() 登记一个 IWorkflowBusinessHandler（Contracts Workflow/）：描述（业务码即流程定义名、单据组件、发起变量、允许的结论、缺省定义的 WorkflowJson）、办理前校验、改动前校验（转办、加签、发起人撤回与管理员的取消、终止、重试、挂起、恢复之前；只读，不过即拒绝，批量里那一项记失败、不交给引擎）、结论回写、中止回写与单据数据。同一业务码登记两次，宿主启动即失败。

业务包经 IWorkflowBusinessService（Workflow 关掉时没有实现，以 IEnumerable<> 注入）发起、撤回与查进度：

  • 发起：业务码即定义名，单据 ID 写进关联 ID；当前分区还没有这个名字的定义时按缺省定义建并发布（平台与租户各一份）；同一单据已有进行中的实例 WORKFLOW_CONFLICT_005；发起即故障（如首个审批节点找不到人）WORKFLOW_CONFLICT_101，调用方随之回滚。都在业务的事务里，与单据一起提交。
  • 结论回写：顶层实例走到带结论的结束节点时，在同一个事务里调业务的 OnOutcomeAsync；失败即结束节点故障、实例停在故障态，修好后重试再回写。
  • 中止回写：管理员取消、终止（批量，回写失败记为那一项失败，实例照样已中止）与发起人在审批中心撤回（回写失败即整个撤回回滚）之后调 OnAbortedAsync；业务自己经服务撤回的不回调。
  • 进度：一次至多 1000 张单据，每张取最近一次的顶层实例，运行中的带等着办的节点与人。
  • 故障原因：实例详情、审批详情、授权申请进度和故障通知显示的是消息文案。活动抛异常或 Http 活动连不上时，原因只有异常的类型全名（如 System.Net.Http.HttpRequestException），不带目标地址和异常原文，完整异常看应用日志。业务回调返回的错误、HTTP 非 2xx 的文案不受影响。

通知 ​

订阅 workflow.task.created、workflow.task.transferred 与 workflow.instance.faulted（竞争消费），经 Notification 的站内待办投递发「待办」类站内信，链接到审批中心：受理人收待办；被抄送人收抄送并写抄送记录（同一实例同一节点对同一人只记一次、只通知一次）；转办的新受理人收转办；实例故障时发起人收故障。投递至少一次，按消息 ID 去重（sys_workflow_message_receipt）；Notification 没装或投递失败只记日志，不阻断流程。文案按收件人的界面语言出（偏好里同步到后端的语言，经 Contracts 的 IUserLocales，Identity 实现），收件人按语言分组各投一条；没存语言的按这次调用的区域，后台恢复流程（定时、延时、超时）时没有区域，落到缺省区域。

工作台小组件 workflow.todo（我的待办）：值是调用方的待办数，条目是最近到达的 5 条，点开到审批中心直接办理。前端经 registerWorkbenchWidget 把它登记到看板（挂在审批中心页上，模块关掉即隐藏），见工作台。

演示流程 ​

BasicApp:Seed:EnableDemoData 打开时，种子 workflow.demo 在演示租户 demo 里建并发布四个流程（按名字只首写）：

流程走向
demo-expense 费用报销发起人的直属主管或签；金额超过 10000 再由总经理审批
demo-leave 请假两级主管依次审批（找不到人转管理员角色），抄送人事专员；超过 3 天再由人事部审批
demo-procurement 采购指定用户会签与总部负责人审核并行，汇聚后总经理审批；120 秒没办以超时关闭
demo-onboarding 入职设置变量、人事准备（抄送发起人）、导师确认、等 60 秒、逐件起采购子流程、差旅报销子流程

要用的人与组织见组织架构。

模块开关 ​

BasicApp:Modules:Workflow:Enabled=false 时 Workflow 包不装：权限码与页面不下发、操作 404，引擎与九张表照旧（宿主恒装数据库工作流）。

前端 ​

src/modules/workflow：审批中心（待我审批、我已审批、抄送我的、我发起的四个页签与详情抽屉，深链 ?tab= / ?instanceId= / ?taskId=）、流程定义页（元数据弹窗、全屏设计器、发起弹窗）与流程实例页（详情抽屉、按节点状态着色的流程图），两个列表可按列排序，按住 Shift 点列追加次级排序。设计器是 @xihan-flow/*，packages/designers 把设计器预设的定义格式与 WorkflowJson 互相映射，面板只给后端 activity-types 列出的活动。
