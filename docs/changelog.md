# 更新日志

本页记录 6.0 起各版本的变化，适用于评估与升级版本的读者。5.x 的更新日志见 [5.x 文档](https://basicapp.docs.xihanfun.com/v5/changelog)。

## 6.0.0（未发布）

6.0 是一次从零重写：后端基于 XiHan.Framework 5 的能力包与操作契约，前端基于 XiHan.UI，契约层由后端的 `openapi.json` 生成。功能按 5.x 逐项核对过，去处见[功能清单](./features)，动机见[为什么是 6.0](./why)。

::: warning 升级须知
6.0 **不提供数据迁移**。5.x 部署留在 `release/v5` / `hotfix/v5` 维护线；换到 6.0 要新建库，经 `schema upgrade` + `seed` 初始化，再在 6.0 上重录租户与账号。

协议也不兼容：没有 `ApiResponse` 信封、路由由操作 ID 推导、错误是 Problem Details、权限码点分三段、没有按钮码、主键是 UUID、租户 ID 是字符串、时间是 UTC 带 `Z`、没有 `X-Timezone`、去掉了 `hi-IN`。配置节也换了。协议变化与配置对照见[表结构升级](./backend/upgrade#从-5-x-换到-6-0)。
:::

### 架构与协议

- 每个业务能力是一个能力包（`IFeature`），分四层、只能向下依赖，由架构测试守护。可选模块用 `BasicApp:Modules:<名>:Enabled` 开关，缺省都开。
- 每个公开方法是一个操作（`[Operation("<资源>.<动词>")]`），路由、OpenAPI、gRPC 方法与 MCP 工具从同一份登记推导。每个操作显式声明暴露面，超出 HTTP 的逐个登记；只读查询走 GET。
- 成功响应就是 DTO，失败是 RFC 9457 `application/problem+json`，字段级错误放 `errors`。见[接口对接指南](./api-guide)。
- 前端的类型、操作客户端、权限码与枚举由 `openapi.json` 生成，CI 重新生成后比对。
- 文案与代码分离：每个包 10 种区域的消息目录，错误只带键与参数，由宿主按 `Accept-Language` 翻译；平台库 `message_translation` 可以按区域覆盖。
- 接口文档的标题、标签、分组与字段说明本地化。

### 账号与认证

- 登录：密码、邮箱 / 手机验证码、第三方登录（GitHub、Gitee、Google、QQ、微信、企业微信、飞书、钉钉）、双因素（认证器、邮件、短信）、图形验证码、登录节流、账号锁定、自助注册（缺省关）与找回密码（发验证码）。
- 令牌与会话：HS256 访问令牌加不透明刷新令牌，每次刷新轮换；会话门禁、锁屏、按人或按会话强制下线；切换租户换令牌、整页重建。
- 每个账号可以限制同时登录：不允许多端或限定设备数。5.x 只存不执行，6.0 真正执行。
- 个人中心可以停用或注销本人账号，要当前密码；模仿会话不能做，租户所有者要先转移所有权。
- 系统内置账号（初始超级管理员、租户开通时的管理员）不能被停用、删除、锁定或由管理员重置密码，本人也不能改用户名或关闭账号。
- 强制改密（系统参数 `identity.password` 的 `forceChange`，缺省关）：打开后，密码由他人设置的账号凭密码登录要先改密。超管种子同样带这个标记。
- 模仿登录缺省 30 分钟并通知被模仿者（系统参数 `identity.impersonation`，最多 480 分钟）。时长是硬期限：能刷新，但不能续期（5.x 不许刷新）。一条原会话同时只挂一条模仿会话。
- 模仿时不能提交或处理授权申请，也不能动这类审批单。这是 6.0 新加的限制。
- 用户管理多了真实姓名、性别、生日、国家与备注的维护，列表多头像、地区、角色、部门与安全标记，详情看验证状态、双因素、今日统计与当前会话。

### 权限与访问控制

- 授予来自框架 `Security.Database`；Deny、授予与指派的有效期、用户直授、角色继承、限时委托、套餐门控、ABAC 条件逐层收窄。
- 权限目录由代码登记、从操作登记派生，页面只读；权限名按界面语言显示。
- 数据范围（角色与用户级）在查询里显式套用，字段安全按实体、字段与角色 / 用户 / 部门配置六种读取方式，在投影时套用。
- 访问策略分平台与租户两层、三个时机、六个模板，能试运行并记命中，有防自锁；登录失败自动封禁。
- 约束规则五类（SSD、DSD、互斥、基数、条件）与会话角色激活。
- 授权申请：为自己申请角色或权限，提交即发起审批，通过即自动授予；工作流关掉时照常列出、不能提交。
- 与 5.x 不同：启停并入修改权限；角色的收回权限、移出成员、解除上级并入授予的那一个码；角色类型只留内建标记，成员上限改配基数约束；菜单的页面节点由各包登记生成，只调展示，没有按钮节点。

### 组织与租户

- 部门（闭包表）、岗位、部门成员；部门支持关键字搜索，带类型与联系方式；归属带备注。
- 租户开通三步（创建、可选初始化独立库、初始化管理员）、停用恢复、换套餐、配额、到期生效、所有权转移、运维支持成员。
- 租户的用户列表带出在别处注册、生效中的本租户普通成员（外部成员），能配本租户的角色、部门、数据范围与直授；账号本身只有注册地与平台能动。
- 套餐：价格、计费周期、配额、权限白名单、启停。停用的不能再分配给租户，已绑定的不受影响，缺省套餐必须启用；这一条后端也拦（5.x 只在下拉里滤掉）。
- 平台数据不实现 `IMultiTenant`，平台与租户两侧严格分开；租户库实体可随租户分库。

### 消息与协作

- 通知公告：定向投递、横幅与弹窗、强制阅读、提醒、阅读统计；正文支持 Markdown 编辑器。
- 收件箱、消息模板（邮件、短信、站内通知、机器人，Scriban 变量，租户覆盖平台模板）、邮件短信发送记录、多通道配置、群机器人（钉钉、飞书、企业微信）、Telegram 机器人。
- 在线聊天：单聊、群聊、部门群（随部门归属自动进出）、助手会话；撤回、编辑、表情回应、置顶、提及、已读回执、正在输入。转发由服务端一次完成，附件以会话为访问范围。聊天审计、敏感词与保留清理（参数 `chat.policy`）。
- 实时推送：通知 Hub 与聊天 Hub；配了 Redis 时跨实例，配了 RabbitMQ 时强制下线还由所在实例断开。导出任务与通知发布的进度推到灵动岛。
- 与 5.x 不同：站内通知不能选模板（5.x 前端也恒传空）；短信定时发送去掉。

### 文件与导出

- 上传、秒传、分片上传、签名下载与预览（支持 Range）、元数据、归档、副本与主存储、校验。
- 存储配置支持本地与 S3 兼容服务；不认 `If-None-Match` 的服务可以按条关掉条件写入（OSS、COS 是否认还没有验证）。
- 导出中心以发起人的身份逐页调列表操作，CSV / XLSX 存 7 天；到期的临时文件由作业 `files.temporary.purge` 清理（5.x 没有这个作业）。

### 日志与审计

- 八类日志与按 trace-id 聚合的链路追踪；分表日志有界队列批量写入，保留清理作业。
- 操作日志的描述取操作的本地化标题；数据变更日志区分「恢复」。
- 访问日志与开放接口日志可以按耗时上下限筛选，异常日志可以按发生位置筛选。

### 系统管理

- 参数（平台加租户覆盖、加密值不回显）、字典（树形项）、业务编号、用户设置（跨端同步）。
- 任务调度：代码登记与运行时作业、Cron 构建器与固定间隔、暂停恢复、立即执行、改计划与恢复、失败重试与单次执行时限、运行历史。
- 缓存管理按命名空间列键、查看、修改、删除；服务监控；版本台账与升级记录。
- 表结构升级器：`Schema/<版本>/` 脚本加台账，平台库之后逐个升级已就绪的独立库，升级期间别的节点进入维护模式（503）。
- 开放平台：签名开放接口与自助凭证、OAuth 2.0 / OIDC 服务端、OAuth 应用、我的应用、授权同意。CloudEvents 入站端点（缺省关）。

### 工作流与审批

- 框架的数据库工作流，流程数据按平台与租户分区落表，随业务事务提交或回滚；全屏设计器、发布、版本、挂起恢复、取消终止、重试。
- 受理人可按指定用户、发起人、表达式、角色、部门、部门负责人、岗位、发起人第 N 级主管与主管链配置。
- 审批中心：待我审批、我已审批、我发起的、抄送我的；办理、转办、加签、撤回、审批轨迹。业务包可经审批业务接入。
- 流程故障的原因按看的人的语言显示。活动抛异常或 `Http` 活动连不上时，原因只有异常类型，完整异常看应用日志。
- 与 5.x 不同：设计器没有 Script 节点。

### 代码生成与打印

- 代码生成：数据源、表结构导入、表与列配置、模板维护与预览、生成与生成历史、零代码只读运行时。单表、树表、主从三种模式生成的新包能编译、能过前端门禁。
- 与 5.x 不同：模板按 6.0 的写法重写，引擎只有 Scriban；前端取数走生成的契约，文案按键写；生成到项目只在开发环境且打开 `BasicApp:CodeGeneration:EnableGenerateToProject` 时可用；产物包生成之后从历史下载。
- 打印模板：平台全局与租户模板、按编码解析、数据源经 `AddPrintDataSource` 登记，拖拽设计、样例数据、预览与直打。

### AI

- AI 提供商（OpenAI 兼容，密钥加密，设缺省，测试连接）、提示词、知识库、助手。助手在聊天里流式回复，按知识库回答，以调用方身份调用勾选的工具，没有权限时被拒。
- 与 5.x 不同：平台与各租户各自维护知识、互不可见；回复失败以错误结束（5.x 返回 200 带错误）；检索失败回复失败，不退化成纯模型回答；还被引用的提示词与提供商不能删除；最大输出与温度真正生效。

### 壳层与通用体验

- 管理端壳层从 5.x 搬入：亮暗、主题色、布局、密度、水印、多标签页、收藏、全局搜索、通知中心、分屏、锁屏；偏好与收藏跨端同步。
- SchemaPage：组合搜索、个人视图、列设置、多列排序、树表、行速览、导出与导入。
- 工作台 Workbench：各包登记的指标、图表与列表小组件，看板布局跨端同步，「我的待办」。
- 关于页与内置的「帮助中心」目录（种子只首写，之后可改、可停用、可删）。
- 与 5.x 不同：富文本与 JSON 编辑组件没有搬（5.x 只有演示页在用）；时区目录改用浏览器 `Intl`。

### 配置与运维

- 配了 Redis（绑定 `cache`）即装分布式缓存，配了 RabbitMQ（绑定 `queue`）即装消息代理，不配仍是单机零外部依赖；配了连不上启动即失败，不退回内存。
- 出站地址策略：向用户填的地址发请求时，缺省只能连公网地址（`XiHan:Security:Outbound`）。工作流 `Http` 活动、群机器人 Webhook、SMTP 服务器、AI 提供商、第三方登录与 S3 兼容存储都受约束。**自建 MinIO、内网 Webhook、内网 SMTP 中继、流程调内网服务、本机模型端点要在这一节放行。**
- 平台库可以配从库（`BasicApp:Database:Replicas`）；从库健康探测缺省开（5.x 缺省关），语句超时写 0 或负值启动失败（5.x 当作不覆盖）。见[部署](./deployment#读写分离)。
- SQL 日志、错误日志与慢 SQL 可配；SignalR 的保活、超时与消息大小可配；转发头（缺省只信本机回环）与跨域（不配即不启用）可配。
- 密码哈希 PBKDF2-SHA256，迭代 60 万次（与 5.x 相同）。
- 发送记录、导出任务与助手回复的失败原因只有异常类型，完整异常看应用日志（5.x 把异常原文写进记录）。机器人返回错误时只记状态码，不回显对方的响应正文。
- 通知的 HTML 正文渲染前净化（5.x 直接渲染）；CSV 导出防公式注入，单元格以 `=`、`+`、`-`、`@` 开头时前面加单引号。

### 明确删除

Schema 隔离模式、扫码登录占位、网关灰度转发、服务端 `X-Timezone`、第二套按钮码、`hi-IN`、5.x → 6.0 数据迁移工具、成员邀请、租户的简称域名与 Logo、编辑器演示页、升级的文件更新与滚动重启、虚拟文件系统配置。没有页面调用的 5.x 接口也没有搬，逐项见[功能清单](./features#_6-0-明确删除的)。
