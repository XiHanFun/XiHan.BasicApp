# 设计取舍

本页说明本项目的架构选择、设计原则与已知限制，适用于评估是否采用本项目的技术负责人与开发者。完整的决策记录在仓库 `plans/` 目录的总体方案里（全局决定 D1–D12）。

## 为什么是能力包 + 操作契约

XiHan.Framework 的应用写法是能力包（`IFeature` + 清单）、操作契约（一个方法一个操作）、管道阶段中间件、RFC 9457 错误与按操作 ID 推导的路由。BasicApp 完全照这套写法组织，不保留 Controller、约定扫描或拦截器一类平行机制，换来的是：

- 一份契约同时得到 HTTP 路由、OpenAPI、gRPC 方法、MCP 工具与 AI 工具，认证、租户、权限、校验与审计在各协议上一致。
- 权限目录、菜单、前端类型都从代码登记派生，不用两处维护。
- 每个包自带实体、操作、权限、页面、种子、文案与测试，可以按 Tier 单独理解和裁剪。

## 全局决定

| 决定 | 理由 |
| --- | --- |
| 能力包 + 操作契约；HTTP 路由由操作 ID 推导，错误用 RFC 9457，成功响应不加信封 | 框架的标准写法，一份契约服务 HTTP、gRPC、OpenAPI、MCP 与 AI 工具 |
| 按 Tier 0–3 分包，只能向下依赖，同层经 `Contracts` 协作 | 包的边界清楚，可选模块能整体关掉；层级由架构测试检查 |
| 主键 UUID v7；租户 ID 是字符串；平台数据不实现 `IMultiTenant`；时间统一为 UTC `DateTimeOffset` | 框架仓储对 `IMultiTenant` 严格相等过滤，平台数据放在过滤之外最直接；UUID 时间有序、JSON 即字符串，前端没有精度问题 |
| 权限码 `<包>.<资源>.<动作>`，操作 ID `<资源>.<动词>`，按钮直接用操作的权限码 | 权限目录从操作登记派生，不另维护一套按钮码 |
| 前端接口层由 `openapi.json` 生成，错误按 `code` 分支 | 前后端契约不一致由生成器与 CI 检出 |
| 框架只校验令牌与判定策略；签发、刷新、会话、双因素、第三方登录、模仿都是 Identity 的操作 | 认证流程属于应用，框架保持通用 |
| 表结构由应用管理：`Schema/<版本>/*.sql` + 版本台账，`InitTables` 只开在开发环境 | 正式库的每一步变更可审阅、可重复执行 |

## 设计原则

**装配显式。** 不用约定扫描、`IScopedDependency` 或拦截器。服务在 `IFeature.Configure` 中登记，横切逻辑是管道阶段中间件。一个包提供了什么，以它的 Feature 类为准。

**单一事实源。** 权限目录来自操作登记，菜单来自页面登记，前端类型来自 OpenAPI，枚举文案来自后端消息目录。

**边界刚、内部柔。** 包之间只经 `Contracts` 的接口与消息主题往来；包内部的目录名全仓统一（`PackageStructureTests` 守护）。

**批量优先。** 对已有对象按标识的写操作（删除、启停、授权、撤销）只提供集合入参，单条是一元集合，响应逐项给结果。

**失败以值表示。** 可恢复的失败返回 `Result` / `Error`，错误码 `<包>_<KIND>_<NNN>` 决定 HTTP 状态与 gRPC 状态；异常只用于编程错误与基础设施故障。

**缺省收紧。** 每个操作必须显式声明 `Expose`（编译期诊断 `XHG004`）：管理操作只发布到 HTTP，选定的只读操作才发布到 MCP 与 AI 工具，供内部服务调用的才发布到 gRPC；权限码缺省要求认证。

**文案与代码分离。** 每个包一个消息常量类和 10 种区域的 JSON 文案，错误只携带键与参数，由宿主按 `Accept-Language` 翻译。

## 代价与限制

| 项 | 说明 |
| --- | --- |
| 登记代码多 | 没有约定扫描，仓储、服务、权限、页面、中间件与作业都要在 Feature 里写明；换来的是装配可读、可测 |
| 跨库事务 | 平台库与独立库租户的写入是顺序提交，不是两阶段提交；租户开通这类跨库写路径由操作做补偿 |
| 数据库 | PostgreSQL 是缺省与 CI 口径；读写分离只在 PostgreSQL 上实测过 |
| 单体部署 | 一个宿主装全部能力包；多实例靠 Redis 与 RabbitMQ 共享缓存、消息与实时推送，见[部署](./deployment#多实例部署) |
| Native AOT | 不是目标。SqlSugar、MailKit、Scriban 等依赖不支持 AOT；操作登记仍按框架要求使用源生成的 `JsonSerializerContext` |
